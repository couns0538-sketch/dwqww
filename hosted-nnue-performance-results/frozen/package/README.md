# Bounded hosted NNUE performance pilot

This is a new isolated native Linux pilot for frozen Forge 6.4.10 versus 6.4.9. It has no measured result yet. Root and independent reviewer have reviewed the complete source, package, workflow and stopping rules; this frozen package is `PREREGISTERED_REVIEWED_READY_FOR_SINGLE_PUSH`. Launch once by pushing a fresh matching branch after setting the reviewed ready status; workflow reruns are excluded. No engine games run here.

Both source archives use GCC 14 Release, generic x86-64-v3, strict floating point, no LTO, and at most two build workers. Both full CTest suites must pass. The exact same candidate-commit snapshot and public-update benchmark drivers link to each frozen core. Both NNUE snapshot streams must compare byte for byte; each engine must produce exactly 419798 nodes for `bench 11` before timing. Actual source archives, file manifests, network-bearing source, complete build commands, compiler versions, core libraries, executables, driver sources, compile commands and disassembly are retained before timing starts.

The wrapper pins itself and all descendants to one recorded allowed logical CPU and runs one process at a time. The sole primary workload is a fresh engine process receiving twelve `bench 11` commands and `quit`. Every one of the twelve complete bench records must have 419798 nodes. Process startup, network initialization and teardown are included identically. Primary CPU time comes from `wait4` user plus system time; external monotonic wall time is reported separately. Partial `info time` and NPS fields are never timing inputs.

First run six same-binary baseline/baseline pairs (twelve processes). Every CPU and wall ratio must be within [0.97,1.03], and each metric's median within [0.99,1.01]. A failed primary calibration ends the whole experiment before any A/B. There is no retry, dropped observation, added warmup, changed iteration count or second attempt. After primary calibration, run the independently calibrated public-update kernel diagnostic with the same six-pair gate. A failed kernel calibration prevents kernel A/B; it does not discard primary results. The primary and eligible kernel A/B phases each have exactly six predetermined alternating ABBA/BAAB blocks (24 processes). All subprocesses are fresh, and no owned build or other benchmark runs concurrently.

For each block, divide summed baseline time by summed candidate time. Retain all six CPU ratios and all six wall ratios, then report the geometric mean and the two-sided 95% log-ratio t interval with five degrees of freedom (critical value 2.57058). This assumes approximately normal, independent block log ratios; six blocks provide limited precision. The only positive primary claim allowed is “observed >=3% CPU speedup with 95% CI excluding no gain under this hosted suite”, requiring CPU geometric mean >=1.03, its lower interval bound >1, and wall geometric mean >1. The 3% threshold applies to the point estimate; the interval need not establish a minimum 3% gain. All other completed outcomes are inconclusive or descriptive. A process fault, timeout, count mismatch or altered immutable input invalidates the affected experiment; retain everything and do not retry.

The separate kernel uses `nnue_update_benchmark --group quiet --iterations 2000000`, a fixed corpus and warmup, and checks corpus/output hashes, FP control, corpus sizes and all work counts across every invocation. Its loop CPU and wall times are diagnostic only; external process resource readouts remain archived too. The out-of-line public `nnue::update` call and absent LTO sections are checked in the actual executable. Kernel speed does not establish whole-engine speed, NPS, Windows/Ryzen behavior or Elo.

Run package tests only (no engines or timed workloads):

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s .github/hosted-nnue-performance -p 'test_*.py' -v
```

The workflow allows 18 minutes: six for build/correctness and ten for the finite timing wrapper, followed by evidence preservation. It uploads raw evidence with `always()` and pushes a unique `results/nnue-performance-RUNID-ATTEMPT` branch. Immutable frozen files and package inputs are hashed immediately before timing and in a `finally` block, including failed runs. Uploads and the final preservation step run after ordinary failures; a hard runner loss can still prevent preservation, so such a run cannot support a performance claim.
