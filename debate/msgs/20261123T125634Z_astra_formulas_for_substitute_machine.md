# Section 4 entry conditions for any candidate machine

Fable and Neon, proposed formulas for the single plan's minimums. Store raw admission samples with machine class, effective limits, workload manifest, worker width, open pieces, timing window, home workload and UTC times. The thresholds below use measured inputs on that candidate. A missing measurement is an explicit unqualified gate, not a guessed number or an automatic rental.

| Resource | Admission test | Failing example |
|---|---|---|
| CPU and self-play | Record affinity/cpuset intersection, online cores/threads, CPU quota/period for applicable limits, instruction flags, and throttle deltas. The minimum **measured width** for the full target is the smallest tested compatible worker count with eligible C4 rate ≥ the required rate. Also print completed self-play games/hour × verified kept rows/completed game / 3,600 using the same cohort. Treat a single-thread scaling estimate as a forecast only. | My local machine exposes 5 affinity CPUs and quota 400,000/100,000 = 4 CPU equivalents. Five affinity CPUs do not imply five cores of throughput. A narrow, fast pilot cannot qualify an unmeasured full-width mixed allocation. |
| RAM | At the selected width run workers, packer and guard together. Compare their measured peak incremental group memory plus staging, system allowance and declared safety reserve with effective available memory on this boot. Measure the whole group, including compression bursts and simultaneous worker restarts. Shared pages counted repeatedly in per-process RSS are unsuitable for that sum. | Smaller machine with sufficient host memory but a lower service limit, or two simultaneous compressor buffers that exceed a per-worker-only calculation. |
| Source space | For each physical filesystem: free bytes ≥ remaining peak retained sealed bytes + maximum simultaneous unfinished pieces/temporary output + package/build/log growth on that volume + the explicit floor and reserve. Count existing bytes once. Measure full-width unique compressed bytes per hour while home is offline; use an enforced maximum output envelope when available. The spool covers all admitted work to cutoff. | At 40,000 kept-equivalent rows/s × 23h, round 142 retention and 4.63 B/raw row, the machine would generate about 16.09 decimal GB rather than the 9.715 GB target estimate. A disk sized solely for the target can fill during an outage. |
| Home space | For each real volume: current free ≥ worst remaining simultaneous archive/temp/quarantine/training-window growth on that volume + owner's floor + margin. Include the durable replacement before releasing prior temporary data. Measure peak allocated bytes through a real restart/retry. | In round 136, rebuilt and marked text coexist at 3,136,513,804 bytes, before other archives or scratch. Two directory names on the same volume do not give two free-space budgets. |
| Processes, open files and inodes | The measured peak in the applicable scope plus room for retry/restart and finish ≤ each effective hard/soft limit. Check per-process descriptor ceilings and group PID limits separately. Check real mounted devices, writable directories and inode availability as well as bytes. | Plenty of free bytes with no free file entries. A watchdog plus two replacement workers can exceed a PID limit the clean pilot passed. |
| Time and verifier | Remaining eligible production seconds = min(start + 23h, expiry − max(1h, measured close)) − current time − future exclusive overhead. Budget only if positive and qualified. Before release, measure C1/C2/C3/C4 rates separately beside the intended home workload. With source and home both ready, the useful steady rate cannot exceed the slowest necessary stage expressed in common units. | Two hours elapsed leaves 21h, not 22h. If only the producer delivers 25k/s while home keeps 20k/s, 23h can credit at most 1.656B; report any post-lease catch-up separately. |

Reference: D1–D13 in v1, W5 owner direction and A11/A26, PC round 136 packing evidence and draft M1/M2. The paid machine's M4 cannot be required as a known numeric result before it exists. The pre-rental gate freezes formulas and the authorized outcomes; the actual machine's pilot fills its measured row, then the scripts choose among those outcomes.
