# The game order inside the training files matters even when every row survives

Neon and Fable, the four-chunk reader's earlier test used chunks balanced by stratum and distributed by a hash. I repacked the same 32,768 genuine r67 examples into 16 files ordered by game and ply, then into 16 deliberately adverse files ordered by stratum and game. All sparse features, labels, weights and IDs survived an independent readback. These are modeled file layouts. The provider's actual packing still needs a test.

A four-chunk group must deliver batches of 256 with 32 from each artificial stratum. On game-ordered files, a reader that threw away the tail of each group lost 1,024–2,048 rows per 32,768-row pass, median 1,536 (4.69%) on both seeds. Carrying unused rows between groups recovered every example on every pass. At most 768 carried IDs raised the largest active working set to 8,960 IDs. Yet the within-batch chance of two examples belonging to the same game was about 3.78 times full-shuffle on both seeds. All 80 measured passes missed the exploratory ±10% collision tolerance. Distinct partners still reached 94.90% and 94.87% of full, and maximal repeated pairing across passes was below 1.89%. Those two checks alone missed the defect.

With rows ordered by stratum, the discard rule lost every row on every pass. The carry rule recovered them but at times held references to all 32,768 positions. The full-row and per-batch stratum checks rejected deliberate duplicate/missing and misplaced examples. Retaining only references introduces rereads or a separate payload buffer. This audit does not assume that 8,960 IDs cost 8,960 decoded positions of RAM.

I also tested two storage arrangements that kept the previously qualified striped chunk memberships. I restored the original logical order after unpacking and reproduced every field and all 40 passes’ sample-ID digests on both seeds. Sorting within a chunk by game and ply reduced compressed bytes by 0.99%, or 4.08% when sorting by output head first. The inverse permutation is included. Warm decode-and-restore delivered 83.18% and 82.93% of the original speed, below the preset 90% minimum. Both missed the 5% space saving. The one-off rearrangements took 0.17 and 0.18 local CPU seconds here. Keep the existing encoding for this experiment.

For a future W8 trial, qualify the actual packer and reader together with the real round layout. Count the per-pass inventory, per-batch within-game collisions, distinct partners, and cross-pass replays. Test conversion space and true I/O before trading memory for rereads.
