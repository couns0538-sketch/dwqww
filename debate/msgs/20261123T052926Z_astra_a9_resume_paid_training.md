PROPOSAL A9: Add a tested exit and resume path to W13 before committing paid hours to the 768 or 1024 training.

KIND: test

EVIDENCE: W6 checks an update on the rented card and W8 checks the input stream. Both can pass if the program writes its only checkpoint or exported net to temporary storage on the rented machine. A stopped instance can then lose a nearly finished run. A weights-only restart can also repeat or skip batches and lose optimizer or learning-rate state while still producing a loadable net. PLAN's estimate before disk costs is 15,036 seconds for 40 passes; a failure near the end can consume nearly that whole single-run estimate. The 1024 cost is measured separately. I did not inspect the trainer, which is outside this branch.

COST: reuse the W6 pilot checkpoint and two short continuations, including a fresh process with the rental's local files made unavailable. Price the checkpoint size, transfer time and write pauses on the chosen path. At the W8 planning rate, one pass of 2B rows takes about 450 seconds; one remotely verified checkpoint per completed pass bounds repeat work to about one pass if the transfer keeps up. Use a different interval if its measured cost justifies it and declare it before the long job.

HOW IT IS JUDGED: Fork one short run after step k. Let one arm continue. In the other, stop the process, remove access to the temporary work disk, recover the last complete checkpoint from independent storage, and continue. Record versioned data/recipe manifest, weights, optimizer and scheduler, precision-scaler state when present, RNG, and sampler epoch/cursor. Require identical next row IDs and learning rates, the same completed-step count, and prediction/update parity within W6's frozen tolerance. Interrupt one checkpoint write: restore must select the previous complete checkpoint. Before releasing the machine, reopen the final checkpoint and exported net from independent storage and run the PC's export check. Time that last download/check inside the budget.

WHAT WOULD CHANGE MY MIND: An existing, demonstrated full-state resume from storage surviving loss of the instance, with a test that detects a repeated or skipped batch and verifies the delivered final artifacts, already covers this. If the owner consciously accepts restarting a short run, report the measured maximum work at risk and keep final-weight delivery verification.
