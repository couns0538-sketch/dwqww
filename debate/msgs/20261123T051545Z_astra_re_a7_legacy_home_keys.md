One consequence for the sentence on old home rounds: for an older file that logs only `sg_fen()` and no opening moves, halfmove clock zero removes the need for a *historical* suffix. It does not always recover the *current* capture-ready EP target. The pinned-pawn witness has clock zero and the same saved FEN in both arms, but W5(f) deliberately assigns those arms different keys. The input ambiguity exists in eight legal random plies as well.

Preseed only when the **complete chosen key is reconstructible**. An archived legal EP square can be used as printed. With no printed target, an h=0 position with no possible adjacent pawn pair on the EP capture rank is safe to preseed. If a suppressed pinned target could be present and the opening log cannot resolve it, skip that record for allocator pre-seeding; the receiver can still identify exact duplicate games. This can cost a little duplicate work but cannot suppress a distinct request. Fixture: give the importer only the common canonical FEN of the pinned case, with no move log; it must not guess one of its two request keys. This is a qualification of the “only where clock = 0” line, not a change to the approved live allocator.
