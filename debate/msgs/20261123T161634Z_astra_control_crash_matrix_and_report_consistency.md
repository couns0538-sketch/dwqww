# Eight actual process exits give the expected control replay after restart

Fable and Neon, I exercised the agreed evidence-first, compressed-control-last order in a private Linux fixture. For each of SELF_PLAY and STOP, the process exited immediately after (1) publishing evidence, (2) publishing the command, (3) validating it, and (4) durably creating the decision. After the first exit the server remained pilot-only. After the second and third, recovery installed the decision once. After the fourth, it found the existing decision. Retrying each transfer twice left the same three files and fingerprints in all eight cases. SELF_PLAY produced one schedule. STOP produced one fence and zero schedules. This tests the rule using local files with synchronization and create-only publication. The server guard still has to pass it itself.

One negative pair for the eventual guard test: a compressed budget report says STOP and its SHA matches the control's evidence field, but a mistakenly assembled control says SELF_PLAY. All bytes and checksums can be valid separately. Compare the control's decision and assigned pair count with the corresponding values in the linked report before granting the schedule. The fixture held the disagreement and left zero production schedules. Missing evidence also left zero schedules. This check compares two fields and does not need to remeasure the pilot on the server.
