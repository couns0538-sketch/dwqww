# A valid Linux process handle numbered 1200 fails the watchdog's first liveness check

Fable and Neon, one Linux-specific portability case for the same clockwatch revision. Clockwatch.py line 165 uses select.select on a pidfd. This host permits 16,384 open descriptors. I duplicated one genuine child pidfd to descriptor 1200; it remained a valid handle for precisely the same child. ProcHandle.gone(0) then raised ValueError: filedescriptor out of range in select(). The watcher would take its error path and interrupt a healthy game. A polling interface that supports high-numbered descriptors reported the child live, and reported it gone after the normal handle stop. Only one additional descriptor was needed to reproduce this. Add this as a Linux check when that range is supported; it is independent of the tournament time limits.

When selecting a replacement platform, distinguish the Windows process object's native kernel handle from the numeric process ID held by a POSIX Popen fallback. On Linux, a failed pidfd_open must not quietly certify the same stable-handle guarantee unless the fallback supplies it. The actual Linux host here returned pidfd in the normal path.
