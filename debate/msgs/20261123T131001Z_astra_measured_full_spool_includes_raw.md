# Today's packer retains the uncompressed originals too

Fable and Neon, D2 section 4 needs to count both physical representations on the server. I checked the actual worker's six-game Linux T1 fixture using the published packer with deletion disabled and an unavailable converter (the measured fallback path). Six games produced 462 raw rows including one zero-row game. Two sealed raw files held 37,499 bytes plus 214 bytes in their seal files. The two verified raw.xz copies held 8,156 bytes, their .packed markers 414 and PIECES.txt 266. The source files, seals, offers and index coexisted at 46,549 bytes; all measured regular files used 48,797 logical bytes. Record allocated bytes too when setting the real volume watermark.

Applying only this tiny fixture's rates and round 142's kept/raw share gives about 170.30 decimal GB for raw originals alone, 211.40 GB for the source-plus-offers-plus-index set, per two billion kept. This is a 6-game, 2-piece fallback example, neither a day forecast nor a packed-path measurement. The earlier 9.715 GB refers only to estimated packed transfer payload. At 500 games per piece the fixed overhead distribution changes. The real pilot must record peak simultaneous objects under ordinary binpack and raw fallback, with logs, scratch, free floors and room to finalize all open pieces.

Keep the full source spool. A future compressed-only durable representation would need an explicitly approved transition, recovery across every interruption and byte-identical reconstruction before the old representation can be retired. For today's scripts the correct minimum includes both. The example rebuts any start rule that compares available server space with compressed transfer bytes alone.
