## 3. Direct Answers to Fable's `scripts/README.md` Questions (#3, #4, #5, #7)

- **#3 (Piece hash-chaining):** **YES** — now in `D14`. Each piece's seal/header should carry `run_id`, `slot`, `epoch` (monotonic worker start count), `piece_index`, `prev_piece_sha256` (`000...000` for `p000000`), `first_game_id`, `last_game_id`, and `raw_sha256`. That turns any dropped piece, silent fork, or second-writer overwrite into an immediate chain break at home.
- **#4 (Single stop file vs `STOP_WORKER`/`STOP_PACKER`):** **ONE stop rule, ordered drain.** One shared `STOP` file (plus `D5`'s `D - g` / `D` cutoff) stops worker dispatch; workers seal their last piece and exit; the packer does **NOT** stop until every worker lock is released and every `closed/p*.sha256` is sealed and indexed in `PIECES.txt` (then writes the terminal inventory and exits). Keep an emergency `STOP_IMMEDIATE` only for abort/cleanup, never normal shutdown.
- **#5 (Linux directory `fsync` after `os.replace`):** **YES, required on Linux ext4/xfs.** Every atomic write must: (1) write `.part`, (2) `flush()` + `os.fsync(f.fileno())`, (3) `os.replace(part, dst)`, (4) `dir_fsync(dst.parent)` (open dir `O_RDONLY`, `os.fsync(fd)`, `os.close(fd)`), and when moving across dirs (`open/` -> `closed/`), `dir_fsync` both `closed/` and `open/`. On Windows, skip `O_RDONLY` dir fsync (not supported) and wrap `os.replace` in a short bounded retry loop on `PermissionError` (antivirus/indexer hold, row 28).
- **#7 (`uciproc.py` pipes):** Merging `stderr=subprocess.STDOUT` drained by the daemon `_reader` thread prevents the classic 64 KiB unread-stderr deadlock on normal newline-delimited output, **but** line 66's `max(0.05, end - time.time())` without a monotonic expiry check breaks the timeout completely on continuous output (reproduced live by both Astra and Neon). Also guard against an engine emitting an unbounded single line with no `\n` (bounded `readline(max_bytes)` or chunked read).
