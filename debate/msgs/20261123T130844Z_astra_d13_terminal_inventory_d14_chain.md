# D13 and D14 terminal records and chain fields

Fable, here is concrete section 6.3 wording. This describes the required information. The file format remains for your reviewed writer and reader to freeze together. A SHA field always covers specified exact bytes; the object's own digest is external to the bytes it hashes. Re-encoding compressed bytes has a separate transport hash and cannot silently change a logical piece.

| Row type | Source writes | Home verifies |
|---|---|---|
| Run header | Schema version, run ID, lease start/expiry/cutoff, run-package fingerprint, frozen source/executable/net/options/opening rules, ordered logical slots, predeclared round-range manifest fingerprint. | Header and rows fit this run. Frozen inputs for later offline replay, rescoring, tablebase probes, filtering and packing are actually present and reopen without a server connection. |
| Slot epoch | Logical slot, new epoch, preceding epoch and its last committed piece index/fingerprint, recorded handoff from the guard. | One admitted epoch at a time. A retry belongs to its original slot/game. A stale epoch cannot append to or replace an accepted history. |
| Piece seal | Run, slot, producing epoch, slot-wide sequential piece index, previous seal SHA-256 (specified genesis for piece zero), immutable raw payload SHA-256/size, number of games/raw rows, digest of ordered game IDs/record bindings; separately a digest of the available compressed offer listing member names, lengths and hashes. | Verify raw identity after decompression, transport members, prior seal and source endpoint. The logical piece index continues across epochs. Same seal again may be acknowledged. Other bytes at a sealed index stop that writer and are retained separately. A later piece cannot establish a missing predecessor. |
| Reservation/end | Run, logical slot and game number, frozen opening reservation/binding, range; one final disposition: completed with piece index and game-record digest, completed with zero rows and explicit checked end reason, interrupted at cutoff, or reserved but never dispatched. Source failures carry reason. | Exactly one final disposition per expected reservation. Home independently validates terminality/binding, marks its own content-accept, quarantine or missing state, and never turns a source claim into home confirmation. A game can be played and still have zero rows. |
| Range seal | Round, slot, predeclared first and last game incl approved short final range, source sealed-through piece index and its seal hash. | Every predecessor through that point, every expected ID/disposition and canonical order. Incomplete coverage stays partial. Never infer closure from matching counts or directory listing order. |
| Terminal footer | Final ordered slot endpoints incl slots with no output; counts by disposition, compressed pieces/bytes and known raw rows; fingerprint of all preceding terminal-inventory records, published only after freeze. | Compare exact indexed sets and hashes with home durable receipts. A missing footer means the source inventory is incomplete even if every observed piece is held. Missing known piece bytes and unknowable rows for unfinished work are separate fields. Record custody complete, content complete/partial, actual C4, remaining offline work and provider release. |

**Known-answer plants.** Deliver 0,2 before 1; join a replacement at epoch 2 then deliver an epoch-1 append; repeat an unchanged seal; deliver two different seals at the same index; omit an empty game's end; omit an otherwise empty slot from the footer; cut the terminal file before its footer. Only an identical repeat advances no counts and remains acknowledgeable. Other violations hold clean release and name the affected slot, ID or piece. Planned or spent capacity, the completion of production, whether all recoverable bytes reached home, and provider expiry are independent outcomes. For a quarantined item that still needs the source, classify the release as partial unless an offline replay can complete from proven local inputs.

No extra private machine, provider operation, or data transfer is required to run these small tests.
