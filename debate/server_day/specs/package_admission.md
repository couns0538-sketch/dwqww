# Admit the frozen execution package

**Duty.** At the real launch, each stage, restart and closing entry point, prove that the files about to run match the externally pinned package and have three current affirmative reviews. The boot guard already hashes listed bytes during its start. Its check supplies part of this duty. The package admission step must also cover the home entry points, the complete roster of files actually imported or used, and the latest seat decision for each path and hash.

**Inputs and output.** Read the pin from outside the package, the verifier at its pinned path, the approved inventory, the exact package on the intended host and the review ledger. Include scripts, imported helpers, configurations, net, book, fixtures and other frozen dependencies. For every path get the latest decision of Astra, Neon and Fable on its exact bytes. Check each path once and reject links, special files, missing or unlisted executable dependencies. Preserve the approved isolation flags and read-only package after checking. Run-generated records have a run fingerprint and their own verification chain. A decision reports the first specific discrepancy and leaves earlier evidence intact.

**Known answers to check before implementation.**

- Give three files A, B and C three named YES votes each. With all nine votes current and all bytes unchanged, all three can be admitted. Replace C's last Fable YES by a later NOT YET for the same bytes. Exactly two files qualify and the package cannot start. A second YES by Astra does not provide the third seat.
- Change one byte in an imported helper or the owner's policy after an earlier stage. The next entry fails before its first operation. Rebuild a matching manifest inside the altered tree; its outside pin still differs. An identical policy beside the package but absent from the admitted list fails. A helper omitted from the list but imported by the real entry also fails.
- A duplicate path, a symbolic link to the correct bytes, a non-regular object or an unapproved bytecode cache in the package is refused. Run the actual stage isolated with bytecode writes disabled on a read-only package; the repeated inventory hash stays equal. Generated receipts written in the run root do not alter the frozen package.
- Restart with the original admitted tree and the same external ledger, then restart with one dependency changed. The first can continue after the other restart gates; the second stops before a game, control or close action. A document AGREE or a publisher's note cannot stand in for a file YES.
