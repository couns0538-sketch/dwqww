# Fetch compressed server output from home

**Duty.** Home initiates the connection to the pinned server host key. Discover wire offers and package-defined wire control files. Use each valid offer's named wire members, retaining their relative paths. Transfer only the approved compressed forms, including already packed rows; keep final wire bytes unchanged. The packer publishes members before the offer. Custody's independent reread gives the receipt. The fetcher itself adds no rows to C1. No server acknowledgement authorizes deletion. There is no home credential on the server.

**Inputs and outputs.** Take the pinned endpoint and host key from the approved local configuration, the expected run, local receipt keys and lengths, current free room, remote listings and the declared idle limit. Bound paths to the listed grammar and use private partial files. A repeated listing of a receipted key and equal length is discovery only. An explicit confirmation reopens the actual kept bytes through custody, and fetch repairs missing or changed bytes. Preserve a changed offer as evidence alongside the old one; an equal-length fork can first become visible in the terminal inventory. Report listing/offer, member, repeat-transfer bytes and confirmation counts separately.

**Restart and stop.** Measure inactivity from the last byte received on each member. Reconnect after the rehearsed idle limit. Continue a partial only when the full-file hash eventually checks. A failed whole-file hash discards the partial and starts from byte zero while the source exists. At the lease end the independent reporter takes its snapshot immediately. Healthy transfers can finish afterward at their true completion time.

**Known answers to check before implementation.**

- For a 1,000-byte wire member, receive 400 bytes, disconnect and resume the remaining 600. The result is one 1,000-byte member and at most one custody receipt. With a corrupt 400-byte prefix the completed hash fails. Refetch 1,000 bytes from zero; total member traffic in this case is 2,000 bytes, including 1,000 resent. No incomplete object earns credit.
- Present 100 equal-length listings of a previously receipted offer. They produce zero member rereads and zero new receipts. Remove a kept member, then request an explicit confirmation. It must be fetched again and verified; the receipt count stays one. A changed listed length must trigger a check for a fork.
- Use a test-only five-second idle limit: two bytes three seconds apart remain live. Six seconds since the last byte times out even if the socket is connected. At expiry a 400-byte partial of a named 1,000-byte object is recorded as 400 partial and 1,000 whole bytes required, without assigning any row count from the partial.
- An unknown or changed host key stops the connection without an interactive decision. An uncompressed server file, an incomplete offer, or a member name outside the allowed tree cannot enter final local custody. Disable content checking for ten minutes; fetch may continue until its own disk budget binds.
