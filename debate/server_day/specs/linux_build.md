# Build and select a Linux server binary

**Duty.** Build from the frozen loop source using the PC recipe's actual feature switches and the variants allowed by the machine check. Produce plain and correctly profiled builds. Build each eligible variant twice and preserve compiler, inputs, commands, profile identity and resulting binary hashes. A checked reference outside the paid package is supporting evidence. The official package must include the exact builder it will execute.

**Admission and selection.** Make missing, stale or incompatible profile data an explicit failed build. Reject an engine error line, timeout or missing expected evaluator line during profiling, even if a profile file or a zero exit exists. Check the pinned net and options, bench/perft references, fixed games, all ordered rows and end lines. Record the chosen executable hash, which the actual worker also verifies. Compare performance only after correctness holds. Use full-width self-play on frozen paired opening blocks, under the day's load. First time one binary against itself. Set the repetition count and symmetric uncertainty rule before the cross-build timing. Keep raw paired wall times. A material slowdown selects the plain build or a repaired profile. A material speedup selects the profiled build. An unresolved difference permits a correctly profiled binary with “gain not shown”. The pilot still judges its real rate.

**Known answers to check before implementation.**

- Equal hashes for plain and profiled outputs produce the literal result `identical_binary` and no speed comparison. A single binary placed under both labels cannot earn a positive profiling claim. A one-byte source edit, absent profile, stale profile, engine error or absent net startup marker is refused with its cause.
- Compare six fixed games with expected raw counts 86, 101, 0, 127, 81, 67. The sum is 462, and all fields and end lines must match. An extra line feed in the hash fixture changes the expected hash even if its row count stays 86. A legally different emitted move or refused setting fails before the rate test.
- Opening seed `edge3146` mates at ply 7. The opening loop did not complete; there is no sent command and the record states `openingend plies 7 reason nomoves`. With `edge4013` mate is reached on the eighth ply; the opening loop completes, the game command is sent and a valid zero-row game record follows. Both cases must survive the build comparison.
- A host supporting only one instruction variant builds and tests only that variant. At the owner-specified first-hour deadline, use only the owner's declared fallback to a binary which already passed, or stop. Absence of a passing binary never yields a measured production rate.
