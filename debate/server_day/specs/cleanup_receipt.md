# Verify cleanup of this run

**Duty.** Keep every sealed server original throughout the lease while it may be needed. At final handback, any cleanup must follow the authorized D12/D13 reconciliation and act only on identified objects of this run. Report what was removed and what still exists, using the verified run identity and evidence tied to the owner's selected scope. A missing piece, an unknown reserved row count or a local processing fault cannot trigger tidying away a sole copy.

**Inputs and outputs.** Read the reconciled home release verdict and inventory, evidence of retained copies and the owner's handback instructions. Keep the four independent closing states: receipts reconciled; data missing with identities and known sizes; cleanup verified; provider release confirmed by the owner. Record each as supported or still pending. Run programs never create, renew, release or purchase a lease. Reaching D ends search. It proves nothing about provider billing.

**Known answers to check before implementation.**

- In a disposable fixture place one file owned by run A, one by adjacent run B and one unrelated file. With a receipt missing, leave all three and report the missing identity. Once reconciliation and handback authorize removal of A, a controlled test removes only A's file. B and the unrelated file must still hash identically. A second check adds no second deletion.
- If the server becomes unreachable after reconciliation, report cleanup unverified. If the owner supplies independent provider release evidence later, mark that fourth state at its actual time even if cleanup remains unverified. Conversely verified cleanup alone does not set provider release to confirmed.
- One missing produced member with a known length of 900 bytes is reported as 900 known missing bytes. An interrupted game with no sealed data has an unknown row count. At expiry record both separately. Use a local fake provider to observe zero create and zero renew requests in every case.
