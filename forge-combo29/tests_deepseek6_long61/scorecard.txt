## The result that matters

The MultiPV contract is **intact**: 0 violations of distinctness, ordering or legality across 600 reads, and the
first line always equals the reported bestmove. But **MultiPV is not a superset search in this engine** — the top
move itself changes on more than a third of the openings (70/200 at k=3, 76/200 at k=5). Anyone who runs "MultiPV 1"
and "MultiPV 3" and compares the first lines is comparing two different searches, not one search reported twice.

## Two harness bugs I hit and fixed before the reported run (kept, not hidden)

1. At **k=1** this engine prints the plain `info depth … seldepth … score …` form with **no `multipv` token**; k=3/5
   print `info depth … multipv N score …`. My first parser only matched the second shape, so every k=1 comparison
   would have been against an empty list.
2. My first version demanded exactly k lines. **Position 189 has one legal move**, so the engine correctly returns
   one line for any k — the checker now expects `min(k, legal)`.
