# Transposition table audit, 2026-11-13

Branch `cursor/tt-audit-bounds-4ffa`. Implementation commit `782e012abb8f79b3290898222e0e4f9eb5cfbd79`. This report commit is the one that adds this file. Nothing was merged, and `LOCK.md` was not changed.

The engine is forge combo29. The audit covered score bounds, mate-distance handling, replacement, and collisions in `include/forge/search.hpp` and `src/search.cpp`. Builds used g++ 13.3.0, CMake Release, `-O3 -ffp-contract=off -fno-fast-math -march=x86-64-v4`, and the same `FORGE_*` defines as the lock CMake file. Clang was not used: the default `c++` on this machine is Clang 18 and it cannot find `-lstdc++`.

## Confirmed bugs

Three bugs were reproduced on the unchanged baseline objects in `/tmp/forge-base` before the fix.

1. Mate distance ignored the 50-move clock. `score_from_tt` only added or subtracted ply. A mate stored at a low halfmove clock was reused whenever `score_usable` allowed it, including when the mate needed more plies than the halfmoves left before a draw. On `4k3/8/8/8/8/8/8/3QK3 w - - 85 40` at depth 5, a clean search scored cp 994 in 691 nodes. The same search after storing an exact mate of distance 30 on the root and distance 29 on each legal child scored cp 992 in 4933 nodes. The root is a PV node and did not return that mate as `score mate`. The false mate still changed the tree.

2. Checkmate was not stored. After a depth-3 search of `7k/8/6K1/5Q2/8/8/8/8 w - - 0 1` found mate in 1 (`f5f8`, score 31999), the position after that move was absent from the table (`hit=0`). Main search and qsearch returned `mated_in(ply)` before `tt.store`. Non-root stalemate still returns from `is_draw` before the table is probed, so that path was not given a new store.

3. Store always wrote the probe-time slot. Two probes of an empty cluster both received the first slot. Storing a depth-30 exact entry through the second probe, then a depth-1 entry through the first probe, deleted the depth-30 entry. Keys 1 and 2 collided this way on a 1 MB table: after the stale store, the deep key missed and the shallow key held score 111.

## Fixes

`score_to_tt` and `score_from_tt(score, ply, rule50)` now live in the header. The two-argument overload is gone, so both search call sites pass `board.halfmove_clock()`. A stored mate whose distance is greater than `100 - clock` (or any positive distance at clock 100 or more) becomes `ValueNone`. The hash move is kept. Distance 0, the already-mated score `-MateValue`, is kept, including at clock 100. A distance equal to the remaining halfmoves is kept: the mating move is played at clock 99 and the opponent is mated. That matches `Worker::is_draw`, which treats clock 100 as a draw unless the side to move is checkmated.

Current Stockfish `value_from_tt` uses the same distance test (`VALUE_MATE - v > 100 - r50c`, read from master `src/search.cpp` on 2026-11-13) and then substitutes a tablebase-win cap. This engine has no tablebase scores. Returning `MateInMaxPly - 1` would still be a crushing evaluation, so the unusable mate is dropped instead of capped.

Checkmate, and a no-move position that actually reaches the end of the move loop, is stored as `BoundExact` with `score_to_tt(mated_in(ply), ply)` (stored value `-MateValue`) before the return. Qsearch stores depth 0 and eval `ValueNone`. Main search stores the depth it searched. Excluded-move and root-restricted empty nodes still return without a store. Exact replacement is unchanged, so a later exact store can still overwrite this entry. The stored depth is the real depth.

Store no longer trusts the probe slot when the cluster has changed. Under the stripe lock it updates the first occupied entry with the same 32-bit tag, or else runs the same replacement rule as probe: first empty slot, otherwise the lowest `depth - 4 * relative_age`, ties keeping the earlier slot. An unchanged cluster picks the same slot the probe recorded. Both the `FORGE_SPD_TT_NOTLS` body and the locked body use this path. The live build sets `FORGE_SPD_TT_NOTLS=1`.

## Audited and left unchanged

- Bounds are `BoundNone=0`, `BoundUpper=1`, `BoundLower=2`, `BoundExact=3`. The PV flag is bit 2 of `gen_bound`. Tests round-trip all three occupied bounds and the PV bit.
- `ValueNone` (32002) and `MateValue` (32000) fit in the int16 payload. The clamp is `[-32767, 32767]`. A score of 40000 is stored as 32767. The clamp does not destroy mate scores or `ValueNone`.
- Static eval is already clamped to the open interval below the mate band. That was not changed.
- A shallow non-exact store does not replace a deeper score, depth, or bound. It does replace the move when the new move is not none. An exact store replaces a deeper entry regardless of depth. Both match the previous policy.
- Replacement quality is `depth - 4 * relative_age`, with `relative_age = (32 + generation - entry.generation) & 31`. A full cluster drops the lowest depth. After three `new_search` calls without a probe, a depth-10 entry (quality -2) loses to a fresh depth-0 entry.
- Qsearch stand-pat inside the window with no best move stays `BoundUpper`. Promoting that to exact could treat a pruned capture as exact.
- Qsearch still has no `tt_depth >= depth` test. A deeper saved score remains usable at depth 0.
- Main-search cutoffs still require `halfmove_clock() < 90` in addition to `score_usable`. Qsearch uses `score_usable` only. Both clocks under 90 share a score; clocks at or above 90 must match the stored clock. The stored clock is capped at 100, so clocks above 100 compare equal to each other.
- The position key does not include the halfmove clock. Different clocks share an entry, and `score_usable` plus the new mate-distance test are what stop a bad reuse.
- The 32-bit tag does not cover the bits between the low 32 and the cluster index. On a 1 MB table, `key` and `key ^ (1 << 40)` are the same slot. Widening the tag would change the 16-byte entry. That alias is recorded as a limitation, not patched.
- Generation is 5 bits. Thirty-two searches make an unprobed entry look current. Probe refreshes generation on a hit.
- `new_search` increments generation and epoch and does not clear entries.
- `hashfull` still samples the first 1000 clusters and counts only the current generation.

## Limitations

- A mate line that captures or pushes a pawn can still be legal when the stored distance exceeds the current clock. The table does not record that the line resets the clock, so the score is dropped and search has to find the mate again.
- An unusable mate entry stays in the cluster until a store is allowed to replace it. That preserves the mate for a later probe at a clock where it fits. It can also block a shallow bound.
- Non-mate scores are still shared across clocks below 90. That is the existing `score_usable` rule.
- The middle key bits are not part of the 32-bit tag. `key ^ (1 << 40)` aliases on a 1 MB table. The test expects that collision.
- Generation wraps after 32 searches. The age test expects an unprobed depth-10 entry to survive that wrap.
- Exact stores, including a depth-0 checkmate, still replace whatever entry the replacement rule selected.
- Qsearch stand-pat with no move stays an upper bound.
- Non-root stalemate, repetition, and insufficient material still return from `is_draw` without a store. Storing a repetition draw as an exact position score would be path-dependent and was not done.
- Root PV search does not cut off on a TT score. A false mate was not observed as a UCI `score mate` at the root. The failing observation was the depth-5 node and score change above, and `score_from_tt` itself.
- No multi-thread race test was added. The slot is re-chosen under the same stripe lock as the write.
- `TTAuditAccess` is a friend used only by `tt_audit`. It can read cluster index and the verification tag.
- This run did not change account settings, install persistence, or read credentials. Supermemory was unavailable and Adapter was not authenticated; no memory tools were used.
