## Predicted command behavior

These are pre-run source predictions for r15d with the default embedded evaluation and the job's Threads 1 and 2. The code links point to line numbers in the [fingerprinted scratch source](step0-provenance.raw.txt). The UCI reference says `isready` is answered while calculating and `bestmove` ends each search. Its clients ordinarily wait for an active search to stop before changing options or starting another search. The overlap cases below exercise Forge's explicit serialization. [UCI protocol](https://official-stockfish.github.io/docs/stockfish-wiki/UCI-Protocol-and-Stockfish-Commands.html)

| Sequence | Source prediction and deciding observation |
| --- | --- |
| 1. `go infinite`, `isready`, `stop` | `src/uci.cpp:473–489` checks the v3 configuration and prints `readyok` while the worker is busy. The worker waits on `stop_cv` after even a finished infinite search (`347–351`). `stop` sets the locked predicate and the search stop atomic, then waits on `done_cv` (`374–389,890–891`). Require active depth output, one `readyok` before stop, no early `bestmove`, and one legal `bestmove` after stop. |
| 2. Idle `stop` | The locked `!worker_busy` branch clears only the UCI-local ponder marker and returns (`377–380`). Require no idle `bestmove`; a follow-up `isready` and finite search must each answer. Dispatch resets stop and ponder state (`806–818`). |
| 3. Two `go nodes 20000` commands without `stop` | The second `go` calls `stop_search()` before parsing and scheduling its task (`739–740,806–818`). An outstanding first search prints its `bestmove` before clearing busy and permitting the next task (`353–370,384–388`). Require two legal terminal lines. Count cases where the first line was already observed and where it was still pending at the second send. The old search may be cancelled before spending its budget. |
| 4. `ucinewgame` during an infinite search | It stops and awaits the old search before clearing TT and worker state, resetting the board, and emptying the position cache (`490–497`, `src/search.cpp:3284–3287`). Require one legal old `bestmove` and a subsequent `readyok` and legal finite reply. |
| 5. `setoption name Hash value 32` during an infinite search | The option path stops and waits first (`498–499`), then sets Hash (`722–725`, `src/search.cpp:3270`). Require the old legal `bestmove` before the post-option `readyok` and one legal reply from a subsequent finite search. |
| 6. `quit` during `go infinite` | `quit` stops and waits, then loop exit and the guard request worker shutdown and join it (`392–407,892–898`). Forge is predicted to flush one legal `bestmove` before exit. Count the observed disposition separately. The portable shutdown acceptance is timely exit with zero or one terminal line. |
| 7. `go ponder`, `ponderhit` | UCI sets an atomic clock origin inside `Searcher::ponderhit()` (`include/forge/search.hpp:642–646`) and sets the locked hit predicate and notifies (`src/uci.cpp:880–888`). The worker either completes under converted timing (`src/search.cpp:1517–1526,1553–1565,3156`) or leaves the completed-search wait (`src/uci.cpp:347–351`). Require no premature `bestmove` and exactly one legal reply after the hit. |
| 8. `go ponder`, `stop` | The stop bit ends polling and the stop predicate also releases the post-search wait without a ponderhit (`src/uci.cpp:347–351,374–389`; `src/search.cpp:1538`). Require exactly one legal reply after stop. |
| 9. Extend a start-position move list, then switch to a different FEN | `position` calls stop before touching the UCI board and cache (`src/uci.cpp:736–738`). Cache reuses only an exact prior prefix with equal position origin (`78–83`), otherwise rebuilds the board and clears the move list (`84–100`). Check the depth-one root set on the new FEN and on returning to both startpos prefixes. In-flight work uses a copied board (`812,342,345–346`). |
| 10. Illegal move in a list | The parser logs the illegal token and returns after the legal prefix, whose moves were already entered in the board and cache (`src/uci.cpp:102–112`). For the job fixture require exactly one diagnostic and the black-to-move depth-one root set after e2e4. This checks Forge's specified recovery behavior on a malformed UCI list. |
