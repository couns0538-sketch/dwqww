What a TmFinishIteration hold records

A `hold depth D prev P last L remaining R` line means the engine completed depth D, selected its move, and decided to return it without starting D+1. It samples iteration duration only with TmFinishIteration enabled in a time-managed search after any ponder wait. The prior and latest samples start at zero. When an iteration finishes, the engine shifts the latest sample to P and saves the elapsed difference for this iteration as L. The ordinary stop rules run first, so a search can stop without a hold line. See r15d src/search.cpp:2938–2939, 2957–2964, 3055–3058, 3142–3160 and 3211–3224.

R is the time left in this move’s adjusted soft allocation. The engine calculates a soft and hard allocation from the mover’s supplied clock, increment and overhead, then scales the soft allocation using search information including move stability, root effort and score changes. With TmNodeShare off as in this job, R is the integer-truncated scaled soft allocation minus elapsed time. When R is positive, the finish rule needs two positive duration samples. If L is at most twice P, it holds when L² > R × P. If L is more than twice P, it holds when L × P > R². Equality permits another iteration under this test. See include/forge/clock_plan.hpp:25–47, include/forge/tm_finish.hpp:26–36 and r15d src/search.cpp:2673–2683, 3162–3216.

Under NodeClock 1000, elapsed time at each sample is the integer quotient of total search nodes divided by 1000. L and P are differences between these already-rounded readings. A search starts with fresh local counts. The game runner separately charges the mover N // 1000 using the final node-count line, awards the 60-unit increment after a move that fits the clock, and supplies the updated clock on later moves. A hold identifies the engine’s estimate at that point. Establishing how many nodes it saved, which future move used the time, or its effect on game results requires measured comparisons. See nc src/search.cpp:1517–1519, r15d src/search.cpp:1527–1534, 2628–2634, and game26.py:149–161.

Footer coverage. The requested change at original r15d src/search.cpp:3241 enables the node-count line for normal worker completion whenever emit_info is true. It prints result.nodes, assigned from total_nodes() + extra_nodes_ at 3229–3231. Existing early returns precede that block: an empty candidate list or terminal drawn root at 2793–2812, an explicit zero node budget at 2816–2819, an emergency root TT-move answer at 2835–2856, and the already-expired hard-clock fallback at 2873–2877. These cases can bypass the footer. The runner requires exactly one footer before bestmove and stops on its absence (game26.py:94–102). This is a source-level limitation; only a recorded search can establish an occurrence in these games.
