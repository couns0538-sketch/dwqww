The job 22 worker launches one Forge process with subprocess.Popen. It records the child PID, executable digest and Linux process start ticks (field 22 of /proc/PID/stat). Each L1 and L0 worker also resolves the live /proc/PID/exe path. The same PID appears in both color columns of every game receipt, every newgame/readyok receipt, every resident sample and every common L1 barrier. A separate live observer reads each L1 and L0 command line and process start ticks from procfs. It also checks CPU affinity and the digest of the named binary. Linux restricted sibling reads of the exe symlink, which the direct parent worker was able to check.

The worker measures Linux VmRSS after the game loop has received the final bestmove or recognized a terminal opening. It opens /proc/PID/status, retains the literal line with its kB unit, and rechecks the process start ticks. It sends the coordinator PREPARED only after this measurement. The coordinator waits for both builds, sends COMMIT, receives both DONE receipts and then permits another game. The independent audit checks every per-game measurement against the literal VmRSS line, PID, ticks, game start/end timestamps and corresponding coordinator barrier. The public milestone rows must equal the rows at ordinals 1, 1000, 2000, 3000, 4000 and the common final ordinal.

The second observer takes an extra procfs reading while the coordinator writes each designated common checkpoint. It waits for the checkpoint directory to appear after both engines have finished the game. It checks that the coordinator's ready.txt completion marker is absent before and after both reads. The coordinator writes this marker before issuing the next PLAY. These independently obtained samples are in stationary-proc.tsv and can be compared directly to the official readings from the same idle interval.

For L0 the audit checks distinct live PIDs with later process start times, the ten matching L1 game identifiers in order and the exact L1 tail cut at the recorded byte offset. The three terminal L1 opening IDs and their zero-record status are checked separately.
