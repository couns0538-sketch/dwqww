## Node-protocol details

**r3-17:** `Worker::should_stop_with` checks node limits before returning early for helpers (`src/search.cpp:928`). `node_limit_specified_` is enabled for helpers as well as the main worker (`:1615`); node-limited searches therefore also publish/check counts at each searched node instead of only the ordinary 1024-node cadence (`:1050`, `:1191`). Helpers still ignore the clock. Only the main worker sets `stopped_by_nodes_`, retaining the last completed-iteration result behavior. `Searcher::search` resets every worker's local/published counts before starting any helper (`:2025`), preventing previous-search counts from entering the next budget. MultiPV still runs its main-worker/alternate-line path; its parent pending-node accounting is preserved.

This is not a proof of exact shared hard caps under concurrency: simultaneous nodes already in flight remain possible. The branch's test source explicitly permits overshoot, including a +32 allowance in several multi-thread checks. Those assertions were inspected, not executed. The tests also cover reused workers and MultiPV budget behavior.

`apply_position` (`r3-17 src/uci.cpp:46`) changes observable malformed-input semantics. Before, an unexpected token after a valid start/FEN returned without installing the candidate, and an illegal move token discarded the candidate and legal prefix. After, it scans through unexpected tokens looking for `moves`; if none exists it installs the base candidate. At the first illegal move it prints the diagnostic, installs the base plus legal prefix, and ignores later tokens. Invalid FEN still rejects the candidate. The added position-prefix tests encode these cases. Existing t18 fuzz contains malformed positions, so that area overlaps test coverage without demonstrating that the job already contains the fix.

**r3-12:** only the main worker with no parent and `N>0` enables the soft target; hard threshold becomes `min(4*N, UINT64_MAX)`. The loop checks the soft target after completing an iteration. The existing abort path still handles the hard threshold. It emits `info string softnodes nodes ...` on that path. This branch retains the base's main-only node-budget gating and does not include r3-17's helper enforcement; a strict total-worker 4N bound is not established.

The parser shares one node-value field and never clears `soft_nodes` when it later reads `nodes`. Thus `go softnodes A nodes B` remains soft mode with target B; it does not become an ordinary hard-B command (`r3-12 src/uci.cpp:92`). Plain `go nodes B` starts from the default false flag and is unaffected. The added softnodes test uses Threads1 and exercises soft-node cases plus corresponding completed-depth move/score comparisons; it does not cover this mixed-keyword case or multi-thread enforcement. No tests were run here.
