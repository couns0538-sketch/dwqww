r4-08 6766b2cf4e8fd1652df19840947b7926bd5fcd9d
  Only production change: singular_depth becomes max(1,(depth-1)/2) in search.
  It prevents a depth2 singular verification from delegating to qsearch, which
  does not honor the excluded-move restriction. The existing main search does
  honor it. This is a useful local fix for the advertised SingularDepth=2
  setting. Default SingularDepth=7 is explicit in base source; every affected
  default call already computes a depth >=3, so the clamp cannot change the
  default tree. The singular condition also rejects mate-valued TT scores.
  The regression seeds a depth1 lower-bound entry in a queen/pawn position,
  varies SingularDepth 7 vs 2, and requires a resulting child depth>=2 with
  legal result/PV. It does not reconstruct an admitted-writer ledger, prove
  mate distance, or run the known KRK/eight-clock fixtures. Broader 200-position
  checks do verify nonempty PVs starting at bestmove and legality of each PV
  move, not terminal completeness. No implication for the default KRK case.

r4-09 bf6f38b8eb03615e602174faab1fc871ece48634
  Only production change: TTEntry::score_usable in search.hpp. For mate-valued
  raw payloads it rejects current_clock + (32000-abs(raw_score)) >100. For
  below90 cross-clock reuse it additionally requires both stored_clock+depth
  and current_clock+depth <100. Exact clock matches otherwise remain usable.
  This feeds existing main/qsearch cutoff and eval-substitution gates; no TT
  writer/replacement/layout, PV propagation, or score normalization changes.
  The raw TT mate value is already node-relative by the inspected existing
  score_to_tt/from_tt functions, so this distance calculation is in the right
  frame for the specified payload.

  Known endpoint remains admissible to this new predicate: current clock15,
  raw -31982 gives distance18 and 15+18=33; depth9 gives current sum24. Since
  the old predicate already accepted it at clock15, its stored clock must be
  below90; the greatest possible stored sum is 89+9=98. Thus this exact known
  endpoint cannot be filtered by the new rule. This does not predict a whole
  rerun's tree, nor identify its earlier writer.

  Its report explicitly retains all eight depth9 low-clock differences, and
  the test source pins the safeguarded move/score/node values and rejects a
  return to simultaneous lock score/node equality. It prints EQUALITY_FAIL
  for continued differences while the overall regression suite can pass.
  This is not an equality pass. Best moves in the eight fixtures agree; three
  reported scores differ. The report discusses four PV differences, but the
  source test does NOT compare those PVs.

  Useful evidence: direct score_usable fixtures assert clock88/depth16 rejection,
  short-horizon acceptance, and same-clock cases; a real store/probe fixture
  verifies preserved score/depth/clock and rejected reuse. Search tests cover
  a clock95 queen ending and a clock87 parent with a poisoned clock88 child.
  The poisoned search only requires unchanged root score, which the report
  says was already unchanged on the unfixed base; direct predicate assertions
  are the regression-specific check. Its 200-search check validates bestmove
  legality only. The tests use Searcher defaults and do not turn NNUE off.

  Scope caveats: stored depth is not a maximum selective path (the report itself
  notes extensions can reach clock90 from these low-clock roots). Therefore
  clock+stored_depth<100 is an extra restriction, not proof that all searched
  descendants remain before the draw horizon. Likewise current clock plus
  mate distance assumes no intervening pawn move/capture for interpreting a
  value as a rule50 impossibility; the predicate conservatively rejects some
  otherwise usable payloads without tracking such resets. This does not show
  a wrong cutoff, but is a reason not to call it a complete rule50 soundness
  proof. Keep the existing per-node gates; do not weaken them for lock equality.
