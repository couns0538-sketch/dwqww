## Material findings

1. **r3-19 non-BMI2 portability:** `src/eval.cpp:220–221,283–284` directly calls `_pext_u64` without a BMI2 guard. `include/forge/bitboard.hpp:18–20` includes its intrinsics only when `__BMI2__` exists; its new fallback helpers do not protect these direct calls. The base permits portable non-BMI2 targets. Such a build now encounters an undeclared intrinsic or target-option mismatch. This is static evidence, not a captured compiler failure. The required x86-64-v3 target has BMI2, so this does not show a regression on the pinned target.
2. **r3-20 overrides explicit build configuration:** `include/forge/bitboard.hpp:17–19` undefines `FORGE_SPD_SLIDER_PEXT=0` and forces 1 whenever BMI2 exists. An explicitly selected multiply-magic portable build no longer exercises that path on x86-64-v3. The report describes this behavior, but it changes the CMake switch's meaning. This is not an observed illegal move or node-count mismatch.
3. **r3-14 warm option changes retain old score bounds:** `src/uci.cpp:324–325` changes DrawJitter without clearing the TT or learned histories. Ancestor scores stored after jittered draw leaves can therefore survive toggling back to 0, or changing the span, and ordinary TT lookup has no jitter-mode tag. This is a source-derived reuse risk; no warm-state counterexample was run. `tests_r3_14/draw_jitter_test.cpp:41–45` constructs a fresh Searcher for each fixture, so its restore-to-zero check does not cover this interaction. Reported bench resets are not a proof for arbitrary warm searches.
4. **r3-18 exit status alone does not prove all evaluation identity checks:** `tests_r3_18/lazy_eval_identity.cpp:199–200,214–215,262–275` counts refresh-network and total mismatches but returns 0 regardless of those counters. Other incremental-vector checks do fail. The report explicitly claims zero mismatch counters; those text values must be inspected, not replaced by a generic exit-0 pass. The catalog covers update/evaluate rather than the fused Worker path, and direct null checks immediately unmake the null; a null-then-real-move descendant has no dedicated fixture.

## Individual source and coverage notes

**01:** `rule50_damped_static` scales corrected static evaluation after correction history, preserves mate/sentinel values, and leaves the TT raw-eval slot unscaled. `src/search.cpp:142–146,1082–1084,1231–1233` additionally requires a matching stored halfmove clock for TT search-score use while enabled. This addresses cross-clock score reuse for the new heuristic, not the t23 rule-50 traversal differences. With the flag false, the extra predicate returns true and the scaler returns the input. The UCI setter clears hash (`src/uci.cpp:314–317`) but retains learned histories. Consequently switching back to false is not equivalent to a fully cold process after enabled searches; this is a test/replay limitation, not a demonstrated default defect. Included tests cover formula boundaries, raw-eval storage, simple mate preservation, high-clock search and 400 depth-10 legality samples. Cross-clock warm search only has a broad score inequality, not exact fresh/warm equality. The report explicitly leaves ply-limit execution and TSan unverified; the included bulk searches are T1.

**11:** `src/eval.cpp:474–517` implements fixed zero for KK/one-minor/KNNK and a hand-written KBN corner drive, and `src/search.cpp:841–845,885–889` bypasses network/correction history for recognized material. KNNK is not a FIDE dead position: mate can occur and some particular positions are forced wins. The code gives a zero *static heuristic* rather than adding a KNN terminal draw cutoff; do not describe this as a complete dead-position oracle. The KBN formula is not a proof of a forced win from every arrangement. Nonroot insufficient-material shortcuts are bypassed for recognized material at `src/search.cpp:968–981`, but the unchanged root adjudication at `1706–1718` still returns immediately for insufficient-material roots. Thus the report's statement that those king moves are searched needs this nonroot qualification. Toggling clears hash, not histories. Tests meaningfully check option parsing, evaluation routing, material classes, bishop-color formula and legal lines; two corner-drive sequences only show decreasing corner distance, not eventual forced mate. The 205 bulk searches are T1 and mostly short opening playouts. No generic dead-position proof, SMP validation, or fix for current Part 4 is established.

**14:** The offset is `(local_nodes % (2*span+1)) - span`, so it is intentionally traversal-dependent rather than a stable position evaluation. Checkmate retains priority. Stalemate at halfmove 100 intentionally receives jitter and is explicitly tested (`tests_r3_14/draw_jitter_test.cpp:163–164`); plain stalemate at clock 0 remains zero. Insufficient material that also meets the clock/repetition condition can receive jitter as well, so the source comment that insufficient material stays literal zero has an overlap qualification. Tests cover formula, repetition/fifty-move roots and descendants, captures, mate precedence, 400 T1 legality/PV samples, and one T2 start-position search. These are not SMP race/soak coverage or a warm-option-toggle proof. With the value initially 0, old draw scores remain exactly zero.

## Interactions and conclusion

These branches are independent alternatives/optimizations against the same checkpoint, not a tested combined stack. 01/11/14 alter scores or draw routing when enabled; 01 and 11 retain learned histories across option changes, while 14 also retains TT score bounds. Their UCI setters stop search first, which avoids a concurrent flag change in the normal UCI path; direct global assignment during search is not covered. A combined 01+11 build would additionally scale the KBN corner heuristic. DrawJitter can offset draw scores that DeadMaterial tries to keep zero when draw conditions overlap. These interactions were not tested by the standalone fixtures.

18 and 20 both rewrite search.cpp. 19 and 20 both rewrite slider initialization/header code; combining them would retain eval-only PEXT tables while also selecting PEXT for general attacks. Independent T1 parity reports do not prove combined identity, thread safety or sanitizer cleanliness.

None of the six supplies a demonstrated repair of the current Part 4 mate/PV issue, eight under-80 t23 equality failures, or a substitute for the pinned D/E/F race/self-play runs. Do not import reported performance conclusions or change the ongoing experiment based on this review. All current failures and pinned coverage limitations remain in force.
