## Correctness and interaction observations

- **05 TT gate is broader than its “already answers the node” explanation.** `src/search.cpp:1243` suppresses the proposed depth step on `tt_hit && tt_depth >= proposed` alone. The actual cutoff at 1254 also requires usable score, suitable bound/window and clock below90. Thus an unusable/mismatched-clock or non-cutting bound can suppress the adjustment without answering the node. This is a heuristic/specification caveat, not a demonstrated illegal result. Its test has no direct TT-bound/clock or withheld-field-lifetime assertions. The marker is consumed before same-ply verification and cleared after the reduced call; no stale-marker defect found by inspection.
- **04 relief cannot rescue a reply already pruned.** The early `lmr_depth` futility/history/SEE estimates remain unchanged; actual relief occurs later at the LMR call. Move index counts legal moves before these pruning checks, not exclusively completed searches. The updated branch report acknowledges the pruning limitation. No focused boundary test for arrivals6/7, replies4/5, or null/probcut resets is included.
- **03 correction is not independent of NonPawnCorrection.** It reads the already blended corrected-minus-raw eval; enabling the original NonPawnCorrection changes this input. Its 8cp/ply conversion can change several plies and only the subsequent search-depth clamp bounds the result. Tests cover integer formula boundaries and legality, not tactical score/mate correctness or combined options.
- **02 adds to the same quiet score affected by ContHist4PlyRead**, thereby changing move ordering, pruning and LMR when enabled. The threat classifier explicitly uses pre-move occupancy, not attacks after vacating the origin; the added oracle tests the same pre-move definition. It is not a full move-safety oracle. Storage/training is per Worker.
- **06 and 07 substantially overlap each other, but differ.** 06 uses geometric attacks, including pinned enemy attackers, and excludes kings as material attackers/victims; it confirms selected low-depth cutoffs after null search. 07 requires legal captures and non-losing SEE and vetoes the entire null attempt at all eligible depths. Combining them changes when 06 can even trigger; neither branch tests that combination. Neither duplicates a t22 option. The new 06 block restores before the abort return; 07 unconditionally unrolls its temporary null move on normal returns. Predicate tests do not independently prove full hash/history/cache restoration or search correctness.
- These changes leave terminal and legal-move routines unchanged. Their search legality checks use the engine's own legal move generation; they are not independent chess or mate-score proofs. None changes TT publication or synchronization. UCI `setoption` still calls stop-and-join before updating plain global option booleans (`base src/uci.cpp:208–209`), so the newly added globals do not by themselves show a new UCI write/search race. Concurrent direct API callers changing globals are not tested.
