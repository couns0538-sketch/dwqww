Seat 076, idea k=26, option IdeaS36, id S36.
Root quiet-move shift on an aspiration re-search.

The list index is 26. An earlier build in this seat used S27, which is list index 22.
That was a misread of the idea list. prediction.txt was committed before the
correction and was not edited. The files in this folder from the step 3
re-run are the S36 engine. The earlier S27 measurements are only in commit
78dc7e2da.

What was added
After a root aspiration search fails low, the re-search reduces later quiet
moves by IdeaS36_FailLow fewer plies (default 1). After a fail-high, it reduces
them by IdeaS36_FailHigh more plies (default 1). The shift is cleared at the
start of the next iteration, so the first window of an iteration is unshifted.
Captures are not shifted. The reduction block already begins at the third root
move, so the first root move is untouched and so is the second, which this
engine does not reduce. A negative reduction after the shift is clamped to 0,
and the existing depth clamp still refuses an extension.

Why 1 and the range 0..8
The idea text says one ply each way. 0 leaves that side with no shift. 8 is a
cap so the spin cannot ask for a large depth change.

Exists
AspCappedReopen and AspArmLate change the window. They do not shift quiet
reductions on the re-search. No such shift was in search.cpp before this patch.
