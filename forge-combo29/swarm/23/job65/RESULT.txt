THE THRESHOLD HOLDS AT THE END OF A LONG LIST, where the searched position is not the game's start
=================================================================================================
23-F140 refined the trigger to follow the position at the END of the sent move list. Every fixture behind 23-F125/F132/
F133 had that position at the START of a short list. This tests the shape a real GUI or analysis tool produces: a
10-ply preamble, then repetitions of the END position, so the searched position is deep in the list and is NOT the
starting position.

FIXTURES — preamble `d5g5 a1b2 g5a5 b2b3 a5a7 b3b2 a7a5 b2b1 b8b7 b1c2`, cycle `b7c8 c2d3 c8b7 d3c2`, found by search
over legal non-capturing non-checking moves and checked with the corrected key. The searched position differs from the
start in every cell.

P1 HELD (all four validated; searched position ≠ start in all four).
**P2 HELD: the threshold is exactly the same at the end of a long list — 2 searches, 3/4/5 bail.** So the rule does not
depend on list length or on whether the repeated position is the root: it depends only on the SEARCHED position's own
occurrence count. 23-F140's sentence survives the test in the shape real tools use.
