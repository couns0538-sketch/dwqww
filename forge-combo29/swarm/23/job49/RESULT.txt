WHAT THIS CHANGES
-----------------
F98 was an endgame observation (five drawn roots, three draw kinds). It is now a mechanism with a **confirmed
non-endgame instance on a board where a real piece was lost**, and the two findings are connected rather than merely
similar: F60's cost is the cost of playing generator index 0, and F98 is why index 0 is played. The phrase "its first
legal move" in the brief was an accurate description all along; what was missing is that "first" means first **in the
engine's generation order**, which is not the same as the first move a human or python-chess would list.

THE HANDOFF, stated precisely because it is the piece an area-7 code-reading seat can act on
-------------------------------------------------------------------------------------------
The observation is: on the drawn-root path the engine returns index 0 of its generated list, unsearched, with cp 0,
while on the same board without the draw it searches 176,711 nodes and returns a different move. What I have NOT done
is read the code, so I do not know which of these is true — and each implies a different fix:
  - an early RETURN before any root ordering or TT probe happens to hand back the head of the list;
  - a draw test placed after generation but before the search, whose failure path publishes the unmodified list head;
  - a root-ordering step that is itself skipped when the draw short-circuits, leaving the generated order untouched.
I list them as open alternatives, not hypotheses I can rank, because ranking them without reading the code would be
exactly the "invented cause" this seat has been careful not to produce (23-F82's standing rule).

LIMITS: one middlegame position, base build only; the PC build searches on these roots (104 / 56,153 nodes) and so has
