## Reasoning written down before the numbers existed
- K v K, KN v K and KB v K are dead draws by insufficient material; a correct engine should say `cp 0` quickly.
  KNN v K is *not* dead (mate is possible with a helpmate) but is a draw with correct play, so `cp 0` is expected
  from a search that knows it, and a small non-zero `cp` would NOT be a fault — only a `mate` score would be.
- The fifty-move counter at 99 is where I expect the interesting result, because seat 01's S-F5 (halfmove ≥ 100
  adjudicates the root as a draw, 0 nodes, mate-in-one missed) says the engine has a `>= 100` branch with a
  visible effect. **At 99 the engine must still search.** If I get 0 nodes at 99, my harness is wrong, not the
  engine — hence prediction #7's control at 98.
- A threefold repetition only exists in the *history*, and a FEN cannot carry history. So the repetition must be
  reached by `position startpos moves ...`, and the engine may legitimately not detect it (it has no game history
  from a FEN). I therefore predict `cp 0` only for the cases where the repeated position is itself a dead draw;
  for a repetition that is won for one side, a non-zero score is EXPECTED and is not a fault. I will report the
  set split into "dead-draw repetitions" and "won repetitions" and only make the `cp 0` claim for the first.

## Method (fixed before measuring)
- Positions generated by `job2/make_positions.py` with `random.Random(501)`; written to `job2/positions/*.epd`
  BEFORE any search, so the position set is fixed and repeatable.
- Twenty per set. Kings never adjacent, side not to move never in check, no position is a stalemate or a
  checkmate (python-chess filtered).
- The threefold set: 20 games driven by `python3-chess` random play in which a position occurs three times,
  stored as the full `moves` list; the engine is given `position startpos moves <list>` and then `go depth 10`.
- Every `.raw.txt` has a `.meta` beside it (exe path started, sha256, id name, every option line sent).
- Scores are read from the LAST `info ... pv` line; a search with no `info` line at all is recorded as `none`.
