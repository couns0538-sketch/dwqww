## How the numbers were produced

- `positions.py` — 6 FENs, each validated by python-chess (`6/6 valid`), refused
  if the engine would silently search startpos instead.
- `ucidrv.py` — one process per engine run, `bestmove` awaited with a timeout, EOF
  treated as an error, both output streams scanned for `info string invalid FEN`.
- `grid.py` — 8 Hash x 6 MultiPV x 6 positions x 3 repeats = **864 runs per build**.
  Records ms, nodes, depth, bestmove and any failed assertion per cell.
- `mkgrid.py` — renders `GRID.md` from the JSON.
- `analysis.py` — ratios, exhaustive K fits, the per-MPV frontier and its
  misclassification counts, **and the recommendation sentence itself**, printed
  from the fitted ceiling so the prose cannot drift from the rule.
- `check_advice.py` — asserts every stated recommendation (in `FINDINGS.md` and,
  with `--shipped`, in the consolidated report) is no more permissive than the
  fitted ceiling. Proved by planting the `48 MB at 2-3 lines` defect: FAIL, exit 1;
  restored, PASS.
- `patches/patch-a-no-line-clear.patch.txt` — removes only
  `alt_shared->tt.clear()`; built and measured as a second full grid.

## Two corrections to the brief, both measured here

**(a) The `invalid FEN` diagnostic is emitted exactly once per command, not twice.**
`grid.py --selftest` prints:

```
selftest A (isready after position): position=1 go=0
selftest B (no isready): go=1
```

With `isready` it is in the position reply only; without, in the go output only.
Scanning both is still correct — each single-stream scan misses one case — but the
diagnostic *moves*, it is not duplicated. A checker asserting both would always fail.

**(b) `go nodes 200000` does not search 200000 nodes.** It stops when a *finished
iteration* crosses the budget, so cells report 52472 to 199619 nodes. The budget
is also shared with the alternate lines (`extra_nodes_` is added before
`should_stop` tests it), which is why node counts **fall** as MultiPV rises. Every
cell therefore records nodes and depth, and `FINDINGS.md` reports ns-per-node
alongside ms.

## Defect found in my own checker, and fixed

The first `--selftest` run failed for two reasons, both real:

1. I had asserted the diagnostic appears in both streams (see correction (a)).
2. My "does the PV checker accept a legal PV" case used three root-legal moves in

   Fixed by replaying a genuinely legal sequence.

The selftest now passes and is the reason either defect was caught.

## Build note for anyone reproducing this

`/usr/bin/c++` on this image is clang 18 with a default C++ include path pointing
at `/usr/lib/gcc/x86_64-linux-gnu/14/`, which does not exist, so a plain
`cmake -S . -B build` fails with `'array' file not found`. Use:

```
LIBRARY_PATH=/usr/lib/gcc/x86_64-linux-gnu/13 \
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=/usr/bin/g++
```

GCC 13.3 headers are the ones present. `go perft 5` = 4865609 confirms the build.
