switches. The first touches the clock stop path this finding is about, so the re-run is not a formality.

Reasoning: seat 08's own reconciliation (08-F10) says the two stop paths differ — `go movetime` checks the
hard limit inside the search, `go wtime` breaks at an iteration boundary — so on a clock search the tail is
governed by iteration length, not by the stop check. The PC's hard-limit fix should therefore change the
OVER-hard excess (small, near zero already) but NOT the p99/median ratio, which is iteration statistics.
So U1-U3 should reproduce closely, and U5/U7 are where the PC fix could show. 20 positions per clock size,
which at wtime 30000 is the expensive part — hence the background run and the 25-minute push cadence.
