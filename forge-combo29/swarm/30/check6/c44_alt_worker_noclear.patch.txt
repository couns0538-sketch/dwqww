# MOTIVATION: after C31 (deleting the per-line tt.clear()) the MultiPV cost was reduced but not gone.
# At `go nodes 20000` the tree is byte-identical (10,877 nodes at every Hash) while wall time grows
# 21.7 -> 967.8 ms from Hash 16 to 2048 (30-F54). Since the residual is proportional to the table and
# independent of node count, the obvious remaining suspect was the OTHER per-line call:

#     Hash 256 : C31 149  ->  C44 128   (WORSE)
#     Hash 1024: C31  40  ->  C44  23   (worse)
# So `alt_worker->clear()` is NOT the residual, and the residual is still bounded only as "at least one
# more whole-table pass per search" (30-F54). Page faults were excluded (a warm-up search in the same
# process does not help) and hashfill() samples only 1,000 clusters (src/search.cpp:645).
#

# for that decision.
