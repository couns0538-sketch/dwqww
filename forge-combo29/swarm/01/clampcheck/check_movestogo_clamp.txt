EDGE CASES seat 28 did not report, which a latency harness can hit — with the mechanism:
  movestogo 0 = 482.0 ms ; movestogo -1 = 486.6 ms ; NO movestogo = 57.2 ms
  From clock_plan.hpp:37-48, `moves_to_go > 0` selects the even-spread branch:
     movestogo N>0 : soft = available/(min(N,50)+1) + inc*3/4  -> SHORT per-move budget
     movestogo 0/-1: soft = available/divisor + inc*pct/100   (divisor default 5)
  so a NEGATIVE or ZERO movestogo does NOT mean 'no moves to go' in the sense a harness may
  assume: it selects the SUDDEN-DEATH branch, which at a 2000 ms clock gives soft ~398 ms
  against the movestogo-50 branch's ~26 ms — a 18x difference in the other direction.
  A harness that sends `movestogo 0` to mean 'ignore this field' therefore gets the SLOWEST
  plan, not the default one. Send no movestogo token at all to get the no-movestogo branch,
  or the numbers in the first column (none) will not match.
  MEASURED: none = 57.2 ms vs movestogo 0 = 482.0 ms -> 8.4x apart, so the two are NOT
  interchangeable. (The `none` figure is itself small here because the engine finished the
  board early; the mechanism, not the absolute, is the point.)
