# REPORT_v3_total_order — the named next step tested: the picker's tie order is NOT index order

**What this tests:** the handover item from `REPORT_picker.md` — make the picker's sort a TOTAL order
(`score` descending, then **original index** ascending) so it is deterministic, in the hope that identity would hold
and an O(n) handout could then replace the sort.

**The answer: it does not hold. 198 of 200 rows differ, and the total moves +1.5865 %.** So the current sort's tie
order is NOT index order, and the picker's 5.03 % is **not** removable by any comparator change. The lever is closed
for good rather than handed over.

```
change                    —               +1.5865 %         -5.0547 %

rows up / down            —               101 / 97          94 / 106
```

**All predictions confirmed, including the one that mattered.** P1 said identity would fail — 198 of 200 rows do
differ. P3 said the divergence would be **smaller** than the find-max experiment's 5.0547 %, because fixing the tie
order is a smaller perturbation than replacing the algorithm — measured **+1.5865 %**, so yes, and that is a useful
calibration: **the tie order alone is worth about 1.6 points on the total node count**, while replacing the
algorithm's output sequence is worth about 5. P4 was conditional on P1 being refuted, so it never arose.

## What this closes

The picker's `std::sort` at 5.03 % of bench time cannot be optimised away:

- replacing it with find-max changes the search by 5.05 % (200/200 rows);
- reproducing a deterministic tie order changes it by 1.59 % (198/200 rows);
- and because the CURRENT order is neither of those, **the only faithful reproduction is the current code**.

So there is no legitimate speed patch in the picker's sort. Its cost is the price of an ordering that is defined by
libstdc++'s introsort internals and that the search demonstrably depends on — the same conclusion `REPORT_picker.md`
reached, now confirmed from the other direction with a much smaller perturbation.

**For the owner this is a clean stop sign:** do not spend time on the picker's sorting. If the ordering itself is ever
worth changing for STRENGTH, that is a search experiment needing game testing, not an identity-preserving speed patch
— and this measurement says the ordering is worth at least 1.6 % of total nodes, so it is a real lever there.

## The measurement discipline point
