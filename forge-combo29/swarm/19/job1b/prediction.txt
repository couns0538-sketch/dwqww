## What differs from job 1, and why

Job 1 profiled `bench 13` only. That is the right instrument for a pinned node count, but Opus's file 2
(Rule 2) says the owner's PC loads its own king-bucket net, `NNUEArch true`, so the PC's search returns through
`static_evaluate_v3` and NEVER runs the hand-written `evaluate_position`. On that machine the 16.51 % I measured
for `evaluate_position` is worth nothing. So this run:

  (a) uses the new position set `R_1911.fens` (11,192 positions, seed 1911, one position every 7 plies of
      400 random python-chess games) instead of seed 1901's;
  (b) profiles `bench 13` AND a search over the first 200 of R at depth 10, so the number is not one fixed
      position set;
  (c) reports the families Opus names as PC-relevant — move ordering, move generation, `see_ge`, quiescence
      bookkeeping, the hash table — as the headline, with the evaluation families shown separately and
      labelled "not PC-relevant".
