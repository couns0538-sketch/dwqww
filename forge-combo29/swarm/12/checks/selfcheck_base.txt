How to read this
  cloud = median on the 4-core machine these tables came from; ratio = yours / cloud.
  PASS  = within 4x. A machine 4x slower is still fine to play with.
  WATCH = 4x to 10x. Usable; prefer one notch smaller Hash if a search feels slow.
  FAIL  = over 10x, or a run that never completed a search.
  SLOW  = within 10x but over 500 ms absolute at depth 6: your
          machine is fine, this setting is just slow to watch. Drop a notch.
  Reference point: MultiPV 2 at Hash 64 over 200 ms means a machine about 4x this one.

WHICH VERDICT TO TRUST WHEN THEY DISAGREE
  The anchor measures the machine and nothing else; the grid measures the settings on
  that machine. If the anchor is PASS and a grid cell FAILs, the setting is the problem,
  not the machine: use a smaller Hash or fewer PV lines.
  If the anchor is WATCH/FAIL and the grid cells are PASS, trust the ANCHOR: the grid
  numbers are relative to this cloud box, and a uniformly slower machine can still
  finish a depth-6 search quickly while being slow at everything else.
  If both agree, trust both.

The SHAPE is what matters and it does not depend on your machine:
  MultiPV 1 costs the same at every Hash size; the cost is (MultiPV-1) x Hash.
  So if a cell here is slow, halving Hash or dropping one MultiPV line fixes it.

The one setting that is never safe on any machine: Hash 2048 with MultiPV 8
  (8-9 s for `go depth 6`, depth 0-1 on a 5 s clock, on the cloud box).
