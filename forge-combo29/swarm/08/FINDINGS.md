# FINDINGS — seat 08, area 8 (THE CLOCK)

**EVERY line below was measured at Threads 1** with Hash 16, unless the line says otherwise. Seat 04 showed the PC
build gives four distinct SCORES at Threads 4 on one position (+2576, mate 13, mate 18, mate 16) and identical
scores at Threads 1; node counts above Threads 1 are not reproducible either. No harness of this seat ever sent
`Threads` above 1 (grep over every script: zero matches for `Threads value 2..9`), so no score, node count or
timing in this file is provisional.

**THREE METHOD RULES, learned the hard way in this seat, that apply to anyone reading or repeating this work:**

1. **A summary I typed is not evidence, and a small sample is not a population.** Every run file here carries its
   per-run lines; a count is quoted only from a committed file; when the question is a spread, twenty runs minimum;
   and a position sample must span the shape classes or say which one it covers. (Three instances: 08-N1.)
2. **A timeout mechanism must be proved against a case known to return quickly before it may declare a hang.**
   `select()` on a Python text-mode buffered pipe reported 90 s timeouts on clocked searches that actually answered
   in 194 ms, because `readline()` reads ahead into Python's own buffer — the harness would have reported "the sparse
   class hangs", which is false and the opposite of the finding. Prove the timer on a fast case first. (08-N2.)
3. **A count from a different SCALE is not a cost.** A mate appearing is not a centipawn movement: mapping
   `mate N` to 30000 cp produced a meaningless "106x more volatile", and an earlier reading turned a mate score into
   "the one-ply move loses 9 pawns". Report such events as counts of the event, never as a magnitude. (08-F30, F31.)

4. **A static analyser of your own code is a heuristic; its verdict needs the same scepticism as prose.** My harness
   ordering audit produced two false positives — one from counting a `setoption` that precedes the `go`, one from a
   "bestmove wait" pattern that matched a reader helper and stretched the window into the next function. Both would
   have been published as defects in my own harness. Open the flagged file before believing the tool. (08-N4.)

5. **Every reader must be exercised against a FAST path that emits no `info depth` lines** — the built-in book, a
   drawn-root bail, or `go nodes 0`. A reader that waits for an info line blocks forever on exactly those paths, and
   they are fast, so the test costs one run. This single test covers three of this seat's five harness traps. And the
   fix for such a hang is **a timeout per read, not a faster reader**: a 20-minute hang on one process becomes an
   immediate diagnosis at five seconds. (08-N5, and the audit that followed: 60 harnesses safe, the main timing
   harness verified on a book answer in 0.2 s.)
