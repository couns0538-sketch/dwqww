# CHECK of seat 11's S-F1 — seat 27 — CONFIRMS

**Their sentence** (all I used; I did not read or copy their script):
> `position fen` reads only six tokens and the following loop silently discards any extra token, so a malformed
> FEN with junk after the sixth field is ACCEPTED (set_fen itself would reject a 7th field); uci.cpp apply_position.

**My harness:** `check_s11f1.py` (written from the sentence). For 3 base FENs and 6 junk tails it sends
`position fen <FEN> <junk>` then `go perft 2`, and compares with `position fen <FEN>` alone. If the junk were a
7th field the position would be refused; if it were taken as moves the board would change or `illegal move` would
appear; if it is discarded the perft 2 must be identical and no refusal line may appear.

**Planted control (Opus file 2, rule 1):** the same `perft2()` run against a fake engine that answers every
`position` with `info string invalid FEN: planted refusal` — 2 of 2 cases reported `refused = True`. So the
harness can see a refusal when one exists, and the 18 acceptances above are not a blind check.

**Beyond their line** (from the code, `src/uci.cpp:27-58`): `apply_position` stops the FEN at six tokens
(`for (int i = 0; i < 6 && input >> token; ++i)`) and then loops `while (token != "moves")` discarding tokens, so
**every** token after the sixth field is dropped, including a token that spells `moves` many fields later. The
`set_fen` guard that would reject it is real and three lines long (`src/board.cpp:224-228`, "FEN must contain
exactly six fields") but unreachable from `position fen`.

**One correction to my own first idea:** I expected `position fen <FEN> e4 e5` to be taken as a move list, because
`e4`/`e5` are legal-looking. It is not: the engine discards them before reaching the `moves` keyword, which is why
the perft-2 identical results are the right evidence and a "no illegal move line" test alone would have been weak.
