b. The two designs, in ten lines.
   Existing (LmrSignedCorrection):
     * signal = static_eval - raw_eval, i.e. the corrected eval minus the raw one. That difference
       also contains the rule50 damping (rule50_damped_static wraps the corrected eval), so it is not
       purely the history correction.
     * scale: correction_cp / 64, rounded toward zero. So 64 cp of correction = one ply.
     * clamp: the DELTA is clamped to -1..+1 ply.
     * floor: the RETURNED REDUCTION is floored at 0 (adjusted > 0 ? adjusted : 0), so it can never
       push r negative.
     * direction: r - delta, so a positive correction reduces LESS (same sign convention as mine).
     * scope: quiet, ss->static_eval and ss->raw_eval both set, correction_cp != 0. Same site.
   Mine (CorrLmr): signal = the signed history correction only (no damping); scale 1024 cp per ply
   (16x finer); delta clamped to -1..+1; NO floor on the resulting reduction; same site and same
   direction. K is a knob (0..400), the existing one is a fixed check.

   Which fires more often, bench 13, counted at the same site on the same run:
     LMR site reached (quiet moves):                    284,673
     existing: eval available                           273,315  (96.0% of the site)
     existing: correction_cp != 0                       205,385  (72.2%)
     existing: r actually changes                        4,668  ( 1.64%)
     existing: change survives the depth clamp                 3  <- the reason bench 11 and 13 do not move
     mine K=24: r changes                              11,204  ( 3.94%)
     mine K=32: r changes                              46,721  (16.41%)
   bench 16: site 1,097,729; existing changes 66,501; mine K=24 changes 203,690; K=32 347,445.

   The reason the existing switch does nothing on bench 11 and bench 13 is its FLOOR, not its scale:
   with correction_cp/64 and |correction_cp| < 64 most of the time, delta is 0 or the floor cancels the
   +1, and only 3 of 4,668 changes survive into reduced_depth. At depth 16 there is far more reduction
   to work with, and it does move (3024920 -> 2817322).
