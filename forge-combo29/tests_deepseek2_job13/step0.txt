b. How the two designs differ (ten lines):
   1. Both scale the same function (rule50_damped_static) at the same two call sites
      (search.cpp:1474 quiescence, 1663 main search), after correction history.
   2. EvalRule50Damp uses a FIXED divisor of 100: at clock 100 the eval is exactly halved.
   3. Rule50Scale uses a CONFIGURABLE divisor D (my job-12 patch; D=300 is what job 12 measured).
   4. EvalRule50Damp ALSO changes the hash: rule50_score_for_this_clock (search.cpp:205-211)
      refuses a stored score whose rule50_clock differs from the current clock. That forbids
      TT reuse ACROSS clocks, which the fixed-divisor design needs because a score built at one
      clock is wrong at another.
   5. Rule50Scale does not touch that function, so it blocks no reuse (measured: 0).
   6. Neither scales mate scores or ValueNone.
   7. Neither touches raw_eval in the TT: the stored static eval stays unscaled.
   8. EvalRule50Damp is a check (on/off); Rule50Scale is a spin where 0 = off and D = the strength.
   9. With Rule50Scale = 0 and EvalRule50Damp false, the divisor is 0 and neither fires.
  10. With both on, Rule50Scale's D wins the divisor, but EvalRule50Damp's TT guard still applies.
