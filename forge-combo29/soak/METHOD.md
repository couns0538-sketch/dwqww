# Conditions and accounting

The six-hour interval is 2026-11-14 05:32:25–11:32:25 UTC. Phase deadlines, measured from this start, are A 10 minutes, B 70, C 115, D 175, E 220, F 295, G 325, H 350. The final ten minutes are for reconciliation and reporting. Runs are bounded below eight minutes; ordinary batches target four minutes. Checkpoints may be pushed early to keep the interval below fifteen minutes.

Engine inputs are exactly integration bf5574ee654a773f0ef3d06878707056b90cdad7 and lock 16833ecc03b425586f91f4c8834dea8807bf4c22. The reference source/include/CMake tree is extracted into an external VM directory without checking out or modifying its branch. Existing engine files and tests are not edited. Both use the original CMake definitions, strict floating-point options, x86-64-v4 and HiddenSize=256. The host supports AVX-512 and BMI2.

`play_driver.cpp` links the engine objects except the UCI entry point. Each game begins at startpos, uses eight seeded legal random plies, then searches with the requested node or depth limit. Hash is 16 MiB; thread count is explicit. The direct Searcher interface never consults the opening book. The compiled-in network is enabled and no external network is loaded. A fresh Searcher history/hash is used for each game; its state persists between moves of that game.

Every searched position is checked for terminal conditions first. Every returned move must be present in the engine's legal list, and each score must be within [-32000,32000]. The game ends on checkmate, stalemate, threefold repetition, 100 halfmoves, insufficient material, or 300 total plies. Insufficient-material dead positions are tracked separately because they are also terminal in the engine. `moves` means searched moves; the eight opening plies are counted separately. `games` includes only games completed within the batch. A final SUMMARY is necessary for a batch to enter totals. Failed or killed batches are retained and repeated with their original seed; partial results are not double-counted.

For any given batch seed and game number, the opening RNG is independently derived by the documented splitmix function in the C++ driver. `--first-game N --games 1` reruns that game's full history, including every preceding search within the game. The latest complete trigger is written to a VM file before each search. Race batches also print each trigger with FEN, complete move sequence, seed, game number, ply and limits, so diagnostics can be associated with their input.

Normal batch evidence records the command, counts, raw-log hash and all non-trigger output. Full normal trigger traces stay in the VM; a fault record includes the triggering input and complete diagnostic output plus ten reproduction attempts. Faults are recorded, never repaired in the engine. No expected value is relaxed to pass a test.

The official opening archive is fetched from official-stockfish/books and extracted only in the VM. `UHO_Lichess_4852_v1.epd` SHA256: 7a7f6470615a69c6cf23d565417701d38732876f480af90d67b42abade35644a. Official fastchess built in the VM is available at commit 3d7a4db2493fc85a05ef010fd7e13a3884667aa2. No strength or speed interpretation is made.
