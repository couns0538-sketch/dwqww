## Cached refresh routes

`refresh_from_pieces` takes one perspective. The two call sites are the two-perspective wrapper `refresh_cached` and the changed-key branch of `replay_ply`. The first call site handles missing ancestry. The second handles a change in the perspective's own king key. [`src/nnue_v3.cpp:904–909,964–974`, `include/forge/nnue_v3.hpp:253–292`]

| Event | Route and number of perspective refreshes |
| --- | --- |
| New search root | At the root initialization site, `Worker::search` invalidates all v3 stack flags and immediately calls `static_evaluate_v3` for the root at stack index 4. `make_valid` finds no valid ancestor and calls `refresh_cached`, which refreshes White and Black separately. The root call evaluates through `evaluate` and discards its score. Terminal, zero-budget and early-stop roots that return before the initialization site skip these calls. The actual call runs before the main search's TT logic. The adjacent comment's description of lazy root initialization is stale. [`src/search.cpp:2793–2820,2835–2877,2885–2922,3367–3375,3404–3410`, `include/forge/nnue_v3.hpp:142–148,280–292`, `src/nnue_v3.cpp:964–974`] |
| Non-root slot without any valid ancestor | The same `make_valid` branch accepts a non-root index and would refresh both perspectives directly from the current board. Normal active-v3 search seeds the root before descent. Keep this fallback separate from the eager root in the event counts so its actual use is visible. [`include/forge/nnue_v3.hpp:280–292`, `src/search.cpp:2916–2922,3404–3410`] |
| Own king moves to a different bucket with the same mirror flag | For each replayed ply, `replay_ply` starts from the parent kings, reads any king addition from the dirty list, computes each resulting `KingKey`, and compares it with that perspective's parent key. Only the changed perspective refreshes. The other uses a single-perspective update. [`include/forge/nnue_v3.hpp:221–274`, `src/nnue_v3.cpp:699–711`] |
| Own king crosses the mirror line with the same bucket | On a mirrored net, a king crossing between files a–d and e–h changes `flip` between 0 and 7. This refreshes the moving king's perspective even if its bucket stays the same. The other perspective incrementally updates the king feature. The Black-relative transform is `square ^ 56`, which preserves the file. [`src/nnue_v3.cpp:699–711`, `include/forge/nnue_v3.hpp:232–274`] |
| Own king changes both bucket and mirror flag | This is one changed key and one perspective refresh. A separate combined event avoids attributing one refresh twice. A same-key king move updates incrementally. Castling uses the same king-key decision and includes both rook changes in the dirty list. [`include/forge/nnue_v3.hpp:75–79,232–274`, `src/nnue.cpp:535–550`] |

When replay starts below the evaluated slot, a refresh for intermediate slot `k` needs its own placement. The code takes `pieces_of(board)` at `top`, walks later dirty lists from `top` down to `k + 1`, undoes their adds and removals, and supplies the reconstructed bitboards to `refresh_from_pieces`. A TT-supplied evaluation at an intermediate node can leave an accumulator unbuilt and lengthen the replay later. Any refresh inside that replay is still attributed to the move that changed the key or to the missing-ancestor route. [`include/forge/nnue_v3.hpp:253–292`, `src/nnue_v3.cpp:719–723`, `src/search.cpp:1816–1820,2013–2023`]

The board's FEN setter writes both king-square slots. A made king move updates its own slot, castling relocates its rook, and unmake restores the king and pieces. `record_move` captures the mover, captured piece and color from the pre-move board, then invalidates the child's v3 flag. `ensure_piece_diff` builds the ordered column-change list when needed. Quiet moves and noncapturing promotions have two changes, captures including en passant and capturing promotions have three, and castles have four. Null moves flip the side to move and update board-rule state without moving a piece. The child flag is invalidated with `dirty.count == 0`, so a null ply keeps the two king keys and is a zero-column update when reached from valid ancestry. It has no separate natural refresh call site. [`src/board.cpp:337–360,1182–1224,1247–1266,1281–1316`, `src/search.cpp:1267–1274,1336–1367,1394–1409`, `src/nnue.cpp:535–550`]

The scalar reference `evaluate_reference` builds fresh accumulators through `refresh` and `refresh_perspective` directly from the board. The `eval` UCI command and optional `FORGE_NNUE_V3_VERIFY` comparison use that reference outside the cached refresh and workload counter paths. [`src/nnue_v3.cpp:725–746,770–776`, `src/uci.cpp:820–830`, `src/search.cpp:3412–3421`]

## Incremental accumulation and output

| Route | Decision and unit |
| --- | --- |
| `apply_changes_pair` | During `make_valid` replay, `replay_ply` finds both new king keys equal to the parent keys. It updates the two perspective accumulators together and marks that slot valid. Count once per replayed ply. A zero-change null replay belongs here and can also be reported as a subset. [`include/forge/nnue_v3.hpp:221–252,277–292`, `src/nnue_v3.cpp:851–863`] |
| `apply_changes` | The replay pair condition failed and the current perspective's key still equals its parent's key. It applies the same dirty list under that perspective's key while the changed perspective refreshes. Count once per perspective call. [`include/forge/nnue_v3.hpp:253–278`, `src/nnue_v3.cpp:839–849`] |
| `apply_pair_and_evaluate` | `static_evaluate_v3` sees an invalid non-root target and a valid immediate parent. It builds the dirty list and tests both perspective keys. If both match, it marks the target valid and calls this function once. The function stores both child accumulators, chooses the output bucket from piece count, and evaluates using the side to move. Dirty-count zero is allowed. If a key differs, the caller uses `make_valid` followed by `evaluate`. [`src/search.cpp:3367–3402`, `src/nnue_v3.cpp:714–717,879–901`] |
| `evaluate` on a valid slot | If the target flag is already valid, the caller evaluates its two accumulators directly with no update or refresh for this invocation. A valid accumulator contains features, so the output function still computes a score. [`src/search.cpp:3370–3374`, `src/nnue_v3.cpp:816–821`] |
| `evaluate` after reconstruction | If a key changed or the immediate parent is invalid, the caller uses `make_valid` and then calls `evaluate`. This covers the root, the changed-key route, and the longer replay route. Its preceding replay or refreshes are counted separately. [`src/search.cpp:3396–3410`, `include/forge/nnue_v3.hpp:280–292`] |

In this AVX-512 build, `apply_pair_and_evaluate` selects its private AVX-512 kernel. It fuses output with the common ordered two-change and three-change updates. Other shapes, including zero-change nulls and a four-change castle with stable keys, use the private pair kernel and then the output kernel. These still count under `apply_pair_and_evaluate` at the public call site. On a non-AVX-512 build the function calls the public `apply_changes_pair` fallback, so naive function-entry totals there would overlap. `apply_changes_with` selects an explicit kernel for testing and is outside these search call sites. [`src/nnue_v3.cpp:378–438,441–513,865–901`]

## Refresh cache lifetime and counters

An entry holds the last input piece bitboards and the resulting accumulator for its perspective, king bucket and mirror flag. Cache indexing is `((perspective * king_buckets + bucket) * 2) + (flip != 0)`. The test net has eight king buckets, giving 32 entries per worker. The entry reserves `MaxHidden` accumulator lanes and operates on the net's `hidden` lanes. `prepare` seeds each new entry with the feature bias and empty bitboards. [`include/forge/nnue_v3.hpp:61–70,119–148`, `src/nnue_v3.cpp:58–61,823–836`]

| Event | Effect on the cache |
| --- | --- |
| First use of a worker, new net generation, or a different stack size | `prepare` allocates the stack, flags and cache entries and resets both counters. Its guard tests the worker's current generation and stack length. The worker calls it with `MaxPly + 8`. A successful net load increments the generation even if the bytes are the same. [`src/nnue_v3.cpp:666–668,823–836`, `src/search.cpp:3367–3370`] |
| `position` | Stops search and applies or updates the board position. The UCI position cache is separate from the v3 refresh cache. Existing v3 entries survive until the next search prepares with a changed generation or size. [`src/uci.cpp:736–738`, `src/nnue_v3.cpp:823–836`] |
| `ucinewgame` | Stops search, clears the TT and each worker's classic evaluation/search state, and resets the UCI board and position cache. `Worker::clear` leaves `v3_state_` intact, so the v3 refresh entries and their counters persist across games within a process. [`src/uci.cpp:490–497`, `src/search.cpp:1217–1239,3284–3287`] |
| Next search with the same net and stack size | Invalidates v3 stack validity flags while keeping per-key refresh entries and counters. A new worker caused by a Threads resize has its own state, allocated on first use. [`include/forge/nnue_v3.hpp:142–148`, `src/search.cpp:2916–2922,3262–3267,3367–3370`, `src/nnue_v3.cpp:823–836`] |
| `NNUEArch` or `NNUEArchFile` change | The UCI handler calls `clear_hash`, which clears the TT and classic cache. A successful file load assigns a new net generation. The next v3 evaluation then resets its worker cache in `prepare`. Toggling the architecture off and back on with the same loaded net leaves the net generation alone. A failed load or unload leaves no active net. [`src/uci.cpp:588–635`, `src/search.cpp:3272–3275`, `include/forge/search.hpp:479–480`, `src/nnue_v3.cpp:573–577,666–673,823–836`] |

`cache.refreshes` increments at the start of every `refresh_from_pieces` call, including a zero-column cache hit. `cache.columns` sums placements removed from the stored entry and placements added to it, expressed as one weight column per changed `(piece, square)` for that perspective. It excludes incremental update columns, the bias initialization and the destination copy. The AVX-512 `refresh_from_pieces` body batches sources four at a time before copying to the target stack accumulator. Both counters are per worker and accumulate until `prepare` resets them. [`src/nnue_v3.cpp:823–836,904–962`]

## Search paths that bypass a new network output

- The general evaluator can return a recognized endgame score, the classical evaluator or the built-in NNUE, depending on the evaluation gates. The eager v3 root call directly selects the v3 function when active. [`src/search.cpp:1278–1288,1326–1333,2885–2889,2916–2927`]
- Quiescence can return on stop, draw, mate bounds or a usable TT search bound. In check it skips the static evaluation. Otherwise a TT hit with `tte.eval != ValueNone` supplies a raw static value before the normal evaluator, and a usable TT score can replace the corrected value used for stand pat. [`src/search.cpp:1766–1788,1790–1833`]
- Main search can return on stop, draw, mate bounds or a usable TT search bound. Hindsight may use a TT raw eval or carry a freshly computed raw eval into the later static stage. In check it skips static evaluation, an excluded-move search reuses `ss->static_eval`, and the ordinary branch prefers `tte.eval`, then the same-invocation Hindsight value, then `static_evaluate`. A usable TT search score can replace the corrected score used by the search. [`src/search.cpp:1910–1935,1946–2029`]
- The refresh cache stores accumulators and piece placement. Neither it nor the stack's `valid_flags` holds an already-computed network score. The correction-history fields cache indices, while `corrected_eval` reads and combines the current table values. [`include/forge/nnue_v3.hpp:119–148`, `src/search.cpp:1412–1471,3367–3410`]

For the counter reconciliation, compare the sum of natural event counts in perspective units with `cache.refreshes`. Keep root and no-ancestor distinct, and classify changed keys as bucket only, mirror only, or both. Keep ordinary paired updates, single-perspective updates and fused calls distinct. The total number of v3 network outputs includes fused calls, valid-slot output and output after replay or refresh. Those output units are separate from search nodes and cached accumulator refresh units.
