# R1_smp — independent review of the lockless-TT pack

Target (read only through git): commit `893b78d57b4b3b78530291f6cae4f794fde64686` on `opus-smp-layout-20261107`, parent P `7ce10a05`. Reviewer: fable (read-only; nothing built or run). 2026-11-09, ~19:25-20:xx Vienna.

**Verdict: no BLOCKER and no MAJOR found.** The lockless protocol is data-race free under the C++20 model, the Threads-1 decisions mirror P line for line, the encoding is a bijection, and every macro-0 change is preprocessor-guarded. Three MINOR items (one latent crash path, one weak oracle, one exception-safety gap) and four NITs follow.

## Findings, most severe first

### MINOR-1 — stale per-worker `tt_lockless_` survives a mode toggle (latent null-array path)
- `include/forge/search.hpp:493` (`bool tt_lockless_`), `:507` and `:514` (`probe_tt`/`store_tt` test the worker flag first), `src/search.cpp:1956` (set only in `Searcher::search`, never reset).
- Scenario: `Searcher::search` with `TtLockless=true` sets every worker's `tt_lockless_ = true`; afterwards `set_tt_lockless(false)` frees `lockless_clusters_` (`search.cpp:479`) and flips `lockless_`. The worker flag stays `true`. Any entry into the search that bypasses `Searcher::search` — the existing `SearcherTestProbe::run` pattern in `tests/rule50_tests.cpp:14-30` calls the private `Worker::search(Board&, SearchStack*, …)` directly — then takes `probe_lockless` on a null array. UCI and the shipped tests never do this (every UCI search and every test search goes through `Searcher::search`, which rewrites the flag), so it is latent, not reachable today. The opposite mismatch (`lockless_` true, worker flag false) is safe because `probe`/`probe_owned` dispatch on `lockless_` (`search.cpp:321`, `:329`).
- Fix: reset the flag when the search ends (an RAII scope like `TtOwnedScope`, `search.cpp:1945-1951`, setting `tt_lockless_` back to `false`), or read `shared_.tt.lockless()` in `probe_tt` (the field is read-only during a search, so it is as cheap as the worker flag).

### MINOR-2 — the positive control never fails, so CI cannot tell a sensitive fixture from a blind one
- `tests/tt_lockless_tests.cpp:345-351`: the naive-table control prints `INCONCLUSIVE` when it sees no incoherent hit but does not call `check(false, …)`; the exit code is 0 either way. SPEC §5.4 says "reports it as INCONCLUSIVE, not a pass", which the exit code does not honour.
- Consequence: a future change that makes the fixture blind (for example a `matches()` that always returns true, or `hits` counted without validation) would still be green; the only evidence is a log line.
- Fix: fail hard when the control shows zero incoherent hits with a large hit count (for example `control_hits > 100000 && control_bad == 0`), which cannot be flaky because the control runs four rounds of a 24-key, 1-cluster, 8-thread store-every-iteration load. At minimum, the verdict must quote the control line from the CI log, not the ctest result.

### MINOR-3 — `set_lockless` is not exception-safe (P's `resize` is)
- `src/search.cpp:472-484` (`clusters_.reset()` at `:476`, allocation at `:477`): the old array is freed before `std::make_unique<TTLocklessCluster[]>(cluster_count_)` runs. If the allocation throws (2 GB Hash, low memory), `clusters_` is null while `lockless_` is still `false`; the next probe dereferences null. P's `resize` (`search.cpp:257-258`) allocates first and then swaps.
- Fix: allocate into a local, then `clusters_.reset()` / move-assign, then flip `lockless_`.

### NIT-1 — CI no longer compiles the default (macro-0) configuration
`opus_round1/ci/run_ci.sh:21` passes `-DFORGE_SMP_LAYOUT=ON` to all three modes. A macro-0-only breakage (a typo in an `#else` branch) would be caught only by the kit build. Acceptable since the kit hash is the macro-0 proof, but note it in the verdict.

### NIT-2 — no CI evidence of the ON path over UCI
CI release runs `uci_check.py --full` on the macro-1 binary with `TtLockless=false` only (pins = lock pins, a good OFF-path identity check). One extra `setoption name TtLockless value true` + bench 11/13/16 would be a cheap Linux pin check of the ON path; today ON identity rests on `node_identity_threads1` (depth 9, 6 FENs) and the PC kit `-CheckOpt`.

### NIT-3 — double dispatch in the gate build
With macro 1 and `TtLockless=false`, every TT access branches on `tt_lockless_` (`search.hpp:507`) and then again on `lockless_` inside `probe`/`probe_owned`/`store`/`store_owned`/`prefetch`/`hashfull` (`search.cpp:321,329,359,371,449`; `search.hpp:215`). Correct and predictable; only the ABBA/gate can say whether it costs anything.

### NIT-4 — `opus_smp_layout/STATUS.md` at this commit still says "no code yet"
Stale against the code in the same commit; update before Code Review.

## Checked and found OK (evidence in 893b78d)
- **Memory model.** All accesses to `lockless_clusters_[].words` while workers run are `std::atomic_ref<std::uint64_t>` relaxed load/store/CAS: `probe_lockless` `search.cpp:504-505,529`, `store_lockless` `:555-556,573-574`, `hashfull_lockless` `:583`, `debug_entry` `:492-493`. Plain writes exist only in `clear` (`:268`), `resize` (`:250`), `set_lockless` (`:477,480`) and allocation; all are reached only from UCI after `stop_search()` joins (`uci.cpp:147-155`; every `setoption`, `ucinewgame`, `position`, `go`, `bench`, `stop`, `quit` calls it first) or from tests between joined phases. `Searcher::search` joins helpers before returning (`search.cpp:1968`). No `atomic_ref` instance outlives its full expression or `store_lockless`, so the "exclusively through atomic_ref while any exists" rule holds during `clear`. Alignment: `alignas(64)` struct, 8-byte elements, `required_alignment` static_assert (`search.hpp:112-117`). `generation_`, `epoch_`, `cluster_count_`, `lockless_`, the array pointers and `Worker::tt_lockless_` are written only in quiescent phases or (the flag) before `std::thread` creation (`search.cpp:1956` precedes the helper loop); thread start/join give the happens-before. The UCI thread never reads the table during a search (`hashfull` is called only by the main worker, `search.cpp:1728`). Prefetch computes an address only.
- **Relaxed ordering and CAS.** Nothing is published through the table except the two words; a validated hit needs K's low 32 bits == key32 ^ mix32(move_K, D&~GenMask), so any K/D pair from two stores passes only with ~2^-32. GenMask = bits 43-47 = `gen_bound >> 3` exactly (`search.hpp:121`), bound/pv bits 40-42 stay covered. The CAS changes only those bits (`with_gen_bound`, `:168`), so K stays valid whatever D it lands on; a failed CAS just skips the refresh. "D then K" is not an ordering guarantee under relaxed, and none is needed.
- **Single-thread equivalence.** `probe_lockless` (`search.cpp:496-540`) versus `probe_body` (`:281-319`): same first-match hit rule with `occupied()`, same refresh formula, same snapshot fields including refreshed `gen_bound`, same first-empty-slot return, same strict `<` on `depth - 4*age` with the earlier slot on ties, same `cluster_index` as `cluster_for`. `store_lockless` (`:542-575`) versus `store_body` (`:335-353`): identical handle gate, `same_position`, move-only rule, rewrite condition, clamps (score/eval ±32767, depth 0..255, rule50 min 100), `gen_bound` composition; the slot is re-read at store time in both. `hashfull_lockless` (`:573-585`) samples the same `min(1000,count)` clusters with the same predicate and arithmetic. The CAS cannot fail with one thread. No divergence found.
- **Encoding.** `data_word` packs score|eval|depth|gen_bound|rule50|padding into all 64 bits; `key_word` carries move in the high 32 and the tag in the low 32; `decode` inverts both exactly (`search.hpp:136-166`). `mix32(0,0) == 0` by construction (`:123-128`), so zeroed storage is the empty entry and an empty slot cannot hit (`occupied()` false). Every field search reads (move, score, eval, depth, bound, pv, rule50) is in K or covered by the mix.
- **Lifecycle.** `set_lockless` is a no-op when unchanged, zeroes generation and bumps epoch (`search.cpp:472-484`), so handles across a toggle are rejected by the epoch gate (`:550-551`). Bench searcher: `uci.cpp:412-414` sets the mode on a fresh searcher before its searches. Exactly one array is allocated in every path (`resize` `:248-258`, `set_lockless`, constructor).
- **Macro-0 identity.** Only `search.hpp`, `search.cpp`, `uci.cpp`, `CMakeLists.txt` change among engine files; every change is inside `#if FORGE_SMP_LAYOUT` or the `#ifndef` default block; the two `#else` branches (`search.hpp:476-477`, `search.cpp:323`) are P's text verbatim; no new `#include`; no `__LINE__`/`__FILE__`/`__COUNTER__` in `include`/`src`; `assert` is compiled out by `-DNDEBUG` in the kit and `pp_identity.ps1` flags. The `-E -P` identity should hold; the kit hash remains the proof.
- **False sharing.** In P, `nodes_` shares its line with `root_effort_count_`, `pondering_`, `start_`, `local_nodes_`, `all_workers_`, `node_limit_`, `node_limit_specified_` (computed from member order; `root_move_nodes_` ends 64-aligned). `alignas(64)` on `nodes_` and on `local_nodes_` (`search.hpp:473-474`) isolates the only field another thread writes-while-reading (`should_stop` stores, `total_nodes` loads, `search.cpp` P:853-866). `SharedSearchState::stop` shares a line with the TT tail, but every neighbour is read-only during a search; nothing else qualifies. Not excessive.
- **Tests.** Round trip (200k random 16-byte patterns + edge cases + per-bit tag sensitivity) and the differential (300k ops, crowded clusters, clamps, none-moves, `new_search`, `clear`, stale handles, `hashfull`, full-content compare via `debug_entry`) are strong oracles for single-thread identity; `node_identity_threads1` covers the `probe_tt`/`tt_owned_` dispatch. Contention fixture: `payload == f(key)` is sound (moves never none, no clamp, same payload per key; 32-bit tag collisions in the fixed-seed pool are ~1e-6 and deterministic). All test-side sharing is through the table API or atomics; `check()` runs only on the main thread. Ponder case is valid (`movetime 60` gives `hard_limit_ms_ = 50`, `search.cpp` P:1502). Time bounds (120 s, 30 s, 5 s) are generous for TSan.
- **CI.** `$PACK_CMAKE` splits to one token; `-DFORGE_SPD_NNUE_ZMM=0` is global (`CMAKE_CXX_FLAGS`), so the `Accumulator` alignment change in `nnue.hpp:40-45` is consistent across all units and tests. The new tests must pass for `check_known_failures.py` (only `forge_tests` may fail, with the 4 known lines). The `PUBLIC` define keeps `forge`, tests and tools ODR-consistent.
