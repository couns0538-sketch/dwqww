# IDEA_SOURCE — C4 king-bucketed input layer (UCI NNUEKingBuckets + NNUEFile)

Ideas only. No code was copied from any engine or trainer; the implementation (engine kernels, refresh cache,
lazy walk-back with placement reconstruction, v2 file format, trainer model/export, parity and test tools) is
written from scratch for Forge. Every constant (bucket layouts, cache shape, file layout) is our own choice.

| idea | public source (concept) | what we took | what is ours |
|---|---|---|---|
| King-bucketed input layer (several feature-transformer weight sets selected by the own king's square, "HalfKA"-style) | Stockfish NNUE docs, `official-stockfish/nnue-pytorch` docs/nnue.md (HalfKP, HalfKAv2, HalfKAv2_hm): https://github.com/official-stockfish/nnue-pytorch/blob/master/docs/nnue.md ; Chess Programming Wiki, NNUE, "King Input Buckets": https://www.chessprogramming.org/NNUE ; bullet trainer (input buckets): https://github.com/jw1912/bullet , docs https://github.com/jw1912/bullet/blob/main/docs/0-contents.md | the concept: weight set chosen by the perspective's king square | Forge feature index `bucket*768 + (rel*6+type)*64 + (r^flip)` on top of the lock's 768 features (bucket 0 without flip == the lock's `feature_index`); 64-entry map indexed before mirroring, so asymmetric maps (and exact lock replicas) are possible; standard layouts 1/2/4/6/8/16/32 in `tools/nnue/forge_nnue_v2.py` |
| Horizontal mirroring by the king's file | nnue-pytorch docs "HalfKAv2_hm" ("horizontally mirrored"); bullet `ChessBucketsMirrored` input type (same repository) | the concept: flip files per perspective when the own king is on the other half | flip when the own king is on files e-h (folds onto a-d), XOR 7 on the square |
| Accumulator refresh cache ("Finny tables") | Stockfish source comment crediting Luecx (Koivisto) for the idea, `src/nnue/nnue_accumulator.h`; explained in "NNUE performance improvements", https://asteri.sm/files/2024-06-01-nnue | the concept: keep, per (perspective, bucket), the accumulator of the last placement refreshed there and apply only the difference | one entry per (perspective, bucket, flip) with 12 piece bitboards, chunked difference application (64 floats per chunk); placement of an unevaluated intermediate ply reconstructed by taking back later recorded piece changes, so every replayed ply stays valid |
| Feature factorisation (shared "virtual" block during training, folded into every bucket on export) | nnue-pytorch docs/nnue.md ("feature factorization") and docs/features.md (factorizers / virtual features): https://github.com/official-stockfish/nnue-pytorch/blob/master/docs/features.md | the concept | `--king-factor 1`: QAT on q(bucket + factor); the export writes exactly those integers |
| Fail loudly on an unusable net file; check the file size before reading (review fix, 2026-10-27) | QA code review of this branch (request: no silent fall-back to the compiled-in net, error + nonzero exit at isready/go, size check before allocation, "active" line); general defensive-loading practice | the requirements | the exact rule (`options::nnue_v2_problem`), exit status 2 at isready / go / bench, unload-before-load, seek-first size check with `file_bytes()`, the UCI-level test that drives the engine process |
| Forge's own design notes | 5_nnue / 7_history: `7_history/ideas/FORGE_IDEA_BOARD.md` P28 KingMirror (mirroring first, K = 4 buckets, factor block folded on export, "Finny-style cache needed in the same build", NPS caution); Strategist note (kb4hm GrokChess precedent lost games, suspected NPS) | requirements: refresh cache in the same build, NPS measured on the PC, gate only with new data | — |

Exactness argument (own): weights de-quantised as int16/4096 make every accumulator value an integer multiple of
2^-12 below 2^12 in magnitude, so float additions are exact and incremental update, refresh cache and full
refresh agree bit for bit in any order (checked on 102k random plies and in search via lock replicas).
