# S46: auto-promote rule replay simulator (opus, 2026-10-27)

Sol's spec (inventory `S46`): a pure-Python, read-only simulator whose rules come from a JSON config, fed with a
timeline of gate / confirm events, writing a deterministic decision log with a reason per line. At least 10 fixtures
with fixed expected logs, including (a)-(h); one deliberately wrong rule must make the tests fail; same input ->
byte-identical output; a README listing every place where the simulator and the PC script disagree (UNVERIFIED: the
PC script is never run). Reworks: the 16:15 fixtures (i)-(viii), each of (i)-(vi) failing on a rule copy of the
pre-fix script F41CF92F, and (18:05 vote) the step-5 suffix case as a regression fixture.

## Use
```
python -I -B forge_sol_S46_promote_sim_20261027.py --rules config/rules_voted_20261026.json --fixture fixtures/e_hold_reaches_cap.json
python -I -B forge_sol_S46_promote_sim_20261027.py --rules config/rules_voted_20261026.json --set spacing_hours=12 --fixture ...
```
A crew vote changes the config (e.g. `race_hold.cap_hours`, `spacing_hours`, `max_chained_without_cr`,
`cap_late_z.exempt24_stems`, `rollback.window_games`, `step5.src_resolution`), not the code. Log line:
`<PC time> | ACTION | subject | reason`; actions TICK, HOLD, PENDING, PICK, PROMOTE, REGATE, COMBINE_LIST, ROLLBACK,
RESTORE, BLOCKED, WAIT, INELIGIBLE, REWORK, REBUILD, LABEL, SKIP, VOID_RERUN, Z2_RELEASE, Z2_DROP, RECONCILE, CRASH,
ALERT, NOTE, END (final state).

One tick follows the order of autopromote.ps1 896663b0: in-flight reconcile (MED-4), rollback scan (rule 8), chain
scan (rule 1: strength [0,x] H1 + confirm H1, own srand, same conc / opponent / exe, attempt 1, CSV clean; VOID never
H1; missing CSV / RUN_INFO = WAIT; H1+H1 vs an older lock = COMBINE_LIST), race-hold (PR 8/8: hold while another
strength H1 confirm on the same lock is live, 12 h cap from the first eligible confirm, confirm-Elo pick, pooled
tie-break; RH-Q1/Q2/Q3; VOID-HOLD one re-run), the 24 h spacing (CAP-LATE Z: waiver for the e48 re-gate only), at most
2 chained AUTO-LOCKs without CR_PASS_AUTOLOCK_<n>, one promote per tick, exe checks, Z-1, promote, race-loser re-gates
(fresh srand, HELD_Z until G104c H1), Z-2 release/drop, RH-Q2 rework, step-5 rebuild of unstarted net gates (4 per
tick) or labels. Every manifest edit and promote needs a running gate (rule 3, CR L8).

## Simulator vs PC script / spec text: disagreements (all UNVERIFIED, the PC script was not run)
1. **Rollback window.** The S46 spec says "TL/crash in the first 300 games"; autopromote.ps1 rule 8 rolls back on a
   TL/crash in ANY later gate or fuzz using the AUTO-LOCK (any game). The simulator follows the script
   (`rollback.window_games: null`); fixture c2 (TL at game 900) documents it. The 300 text comes from the Deep Research
   S46 proposal, not from the AL vote.
2. **(b) "no 24 h wait" for the losing chain's re-gate.** True under the race-hold PR (F41CF92F gave every race
   re-gate `ag_rebase_exempt24`). CAP-LATE Z 8/8 limited the waiver to the e48-vs-AUTOLOCK re-gate; 896663b0 and the
   simulator follow Z (b1: `exempt24 False`; e/v: `True`).
3. **Step-5 source folder (the step-5 suffix bug).** 896663b0 derives `src_h256_<gk>` from the exe name; a suffixed
   folder (`src_h256_e20i_ep20`, `src_h256_auto000_ep16`, `src_h256_k_ep16`, all present on the PC, listed read-only)
   is not found and the net gate is silently labelled "keeps old opponent". N29 (18:05 vote) wants the manifest
   `src_dir` and a SKIP with a loud rbskip alert. The simulator default follows N29; `rules_pc_896663b0.json`
   reproduces the script. N29's tree-hash and net-md5 checks are not modelled (folder existence only).
4. **MED-5 (open in 896663b0):** a missing or "nan" Elo still picks (`[double]$null` = 0). The simulator does the same
   (no fixture).
5. **MED-6 (open):** the script reads the hold cap from the confirm RESULT.md mtime every tick; a touched file moves
   it. The simulator takes the cap from the confirm's result time in the timeline (no touch events modelled).
6. **L2 (open):** the rival status regex `HELD|PARK|RETIRED|DROPPED|SKIP` is unanchored in the script ("UNHELD" also
   matches); the simulator uses the same regex (`race_hold.rival_off_status_regex`).
7. **N-2:** a PAUSE file without `expires=` falls back to mtime + `$PAUSE_HOURS` in the script; the simulator needs an
   explicit `pause` event with `until`.
8. **Exe checks** (perft5, kiwipete5, FMA 0, bench x2 = gate prebench, uci list) run the real exe in the script; the
   simulator passes them unless a fixture sends `exe_check_fail`. The nps check is warning-only in both.
9. **Lock kind net/search** is a tree diff against the lock's SOURCES.sha256 in the script; in the simulator it is the
   fixture field `kind` (net = only src/nnue_weights.inc differs), assumed to stay net-only against a net lock.
10. **Manifest edits:** the script retries 3 times, waits for a 2-min stable mtime, backs up and refuses if the file
    changed; the simulator applies an edit at once while a gate runs, otherwise defers it to the next tick.
11. **Not modelled:** Fuzz-State, the datagen switch (rule d), pins (rule 4), desktop export / zip, the 2-h WAIT_DATA
    alert clock (taken from the result time), RUN_INFO sha reads (Ran-Sha uses the manifest base at gate start), a
    second VOID re-run (code path present, no fixture), a crash BEFORE the pointer write (BLOCKED path present, no
    fixture).

## Limits / UNVERIFIED
The simulator models the rules, not the PowerShell code; agreement with the script is shown only by the real
2026-10-25 replay (13/13 decisions) and by QA's scratch runs listed above. Everything else is UNVERIFIED.
No promote decision on the PC was triggered or influenced.
