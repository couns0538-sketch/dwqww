forge/r65 = forge/r15dsg (the tree of the loop's exe) + the compile switch FORGE65: the PLAY build "Forge 6.5"
(Fable, 2026-11-23 PC clock; the owner's order of 23 November 2026, teamwork/OWNER_ORDER_2311.md).
NOT IN THE LOOP and not meant for it: the loop keeps forge/r15dsg and runs/forge/engines/v3-r15dsg-sp-clang/forge.exe.

WHAT IT IS FOR
The owner downloads one program that plays as the loop's engine does with nothing to set: the net inside the exe,
the loop's settings active from the first line.

WHAT CHANGES (all of it inside "#if FORGE65"; without -DFORGE65=1 the tree is r15dsg)
- include/forge/forge65.hpp, src/forge65.cpp (new): the net's bytes (#embed "forge65_net.fnn3") and the start-up
  lines: ALL 24 setoption lines the loop sends (Threads 1, Hash 16, OwnBook false, the 19 search settings,
  NNUEArchFile, NNUEArch true), in the loop's order; only the net's path is "<forge65>" = the net inside the exe.
- src/forge65_net.fnn3 (new): runs/forge/r0067/train/cand.fnn3, sha256 737f197808fef489..., 9,463,528 bytes
  (the loop's best net since round 67).
- src/nnue_v3.cpp, load(): the path "<forge65>" takes the built-in bytes; every other path is a file as before.
  The built-in bytes pass through the same checks as a file's.
- src/uci.cpp: (1) before the first input line the start-up lines pass through the engine's OWN option handlers,
  exactly as when the loop sends them; (2) the "uci" answer says "id name Forge 6.5", "id author Couns" and lists
  every switch with its LIVE value as the default (a chess program that sends every listed default back must
  change nothing), Hash with the start-up value 16; same options, types, ranges and order as r15dsg.
Nothing in search, evaluation, move generation, time handling or the selfgame command is touched.

BUILD
forge/tools/build_forge65_clang_pgo.sh <out_exe> <net.fnn3> = the loop exe's own recipe
(build_forge_v3r15dsg_sp_clang_pgo.sh: clang 23.1.5, -march=znver5, ThinLTO, profile-guided with bench 11 / 13 / 16
on the net and 60 self-play games through pgo_selfgame.py, GCC's libstdc++) with -DFORGE65=1 added; it stops when
src/forge65_net.fnn3 is not the net named for the profile step.
The compiler's one note per build pass: "#embed is a Clang extension [-Wc23-extensions]" (forge65.cpp line 13).

HISTORY
- exe_p1 (built 2026-11-23 01:49:36, sha256 627930ab...): the first design left Threads, Hash and OwnBook to the
  engine's defaults (1, 32 MB, book on). Its checks were met (Fable 13 of 13; Opus: pins, 200 of 200 openings equal),
  but Opus's runner showed two listed defaults that differ from the loop (Hash 32 against 16, OwnBook true against
  false) and, on 400 game positions at depth 12, equal best moves with other node counts (24,331,783 against
  24,384,618): Hash. The owner's word is "make sure everything matches fully", and the opening book never played
  in a measurement of ours, so the design was changed to the loop's whole list. exe_p1 was never published.
