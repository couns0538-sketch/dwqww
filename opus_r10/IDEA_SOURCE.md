# IDEA_SOURCE (R10, HalfKA / K32H3^ inference for nets from the nnue-pytorch trainer)

No Stockfish or nnue-pytorch source is in Forge's `src/` or `include/`: `src/nnue_halfka.cpp`,
`include/forge/nnue_halfka.hpp`, the search/UCI wiring and every tool here are new code. The format and arithmetic
were read from the trainer clone the PC already uses (`F:\opus_scratch\r6\nnue-pytorch-amd`, nnue-pytorch b2614500 +
R6 patches, GPL-3.0) and re-implemented; the two Python test helpers (`parity_nnue_pytorch.py`, `make_init_net.py`)
import the trainer at run time from that clone and are tools, not engine code.

| source (licence) | what it defines | idea taken | where in R10 |
|---|---|---|---|
| nnue-pytorch `model/utils/serialize.py` (GPL-3.0) | `.nnue` layout: version `0x6A448AFA`, network hash = fc hash ^ feature hash ^ 2*L1, description, FT hash = feature hash ^ 2*L1, int16 FT biases, FT weights per feature segment (int8 for K32H3), 32 layer stacks each with its fc hash, int32 biases and int8 weights `[out][in padded to 32]` for l1 / l2 / output; the fc-hash recurrence | the file format and the hash checks; L1 recovered from the FT hash, (L2, L3) from the network hash plus the exact file size | `load()` |
| nnue-pytorch `model/modules/features/k32h3.py` + `data_loader/cpp/training_data_loader.cpp` (GPL-3.0) | K32H3: orientation (vertical flip for Black, horizontal mirror when the own king is on files a-d), 32 king buckets of the oriented king square, 3 states (opponent queen / any rook or queen / none), piece plane = type * 2 + (colour != perspective), export merges both kings into plane 10 (704 planes per bucket, 96 buckets) | feature indexing and the bucket rule; refresh when the own king square or the state changes, incremental updates otherwise | `feature_bucket()`, `feature_index()`, `Worker::halfka_evaluate()` |
| nnue-pytorch `model/modules/feature_transformer/double_ft_functions.py`, `model/quantize.py` (GPL-3.0) | FT: [side to move, other side] accumulators, clamp to [0, 255/256], pairwise product of the two halves; quantization constants (FT one 256, hidden one 128, weight scales 128 / 64 / 128, l0 division 512, sqr division 128, nnue2score 600, output scale 16) and the fake quantization (`floor(x * 128 + 1e-5)`) | the integer forward pass: `a*b >> 9`, `s >> 7` / `s >> 6`, squared activations `(s^2 + 20) >> 21` / `(s^2 + 5) >> 19` (the `+ 1e-5` of the fake quantization made exact), output `trunc(2 * total * 9600 / 32768)` | `evaluate_raw()` |
