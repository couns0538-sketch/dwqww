# Exact performance and NNUE

Profile the actual Release engine before choosing a kernel. Separate wall-clock search speed, CPU utilization, allocations and a synthetic kernel benchmark. Use perf or a platform profiler when available; a missing profiler is not a reason to invent hotspot evidence. Measure representative positions/endgames, search threads and normal TT occupancy.

For exact-speed work, freeze each arm's own source revision and binary. Keep input/openings, network, options, evaluation and floating-point operation order equivalent between arms. With no-FMA contracts preserve `-ffp-contract=off -fno-fast-math` (or the documented toolchain equivalent), inspect emitted code in the NNUE scope and count all relevant fused multiply/add variants with a defined disassembly method. A grep for one mnemonic is insufficient on a different ISA. Record optimizer/LTO/PGO/ISA flags; `-march=native` is not a portable Windows release recipe. Detect supported target instructions, alignment and scalar fallback. Never substitute a different net to achieve matching nodes.

Use wide integer references for integer inference. Prove accumulator bounds **for every supported net**: biases, maximum simultaneously active features, signed feature contributions, transient add/remove ordering, multiplication widths, clipping and output accumulation. Observed sample extrema are not a proof. SIMD wraparound/saturation can evade UBSan; casts/narrowing and signedness need explicit tests. A loose bound crossing int16 range means safety is unproven, not that a reachable overflow was demonstrated. Tighten that proof or use wider arithmetic before accepting the path. Demonstrated reachable legal or transient overflow rejects int16. Keep int32 when required; do not assume even int32 intermediates cannot overflow.

Compare incremental updates versus a fresh refresh and scalar versus each SIMD path. Cover both perspectives, king buckets, all move classes, long legal playouts and make/unmake, with a deterministic seed. Record counts and first mismatch; do not claim coverage never run. Refresh caches need keys/invalidation for king bucket, perspective, piece state and network identity. Verify that ON actually runs using a once-per-search/session info marker and relevant counters; no hot-path heap allocation or per-node logging unless measured/authorized.

Preserve residual HCE+NNUE semantics and existing net/training infrastructure. Loader tests cover header/version/architecture, sizes **before** reading/allocating the full payload, truncation, oversized input, endianness, and clean rejection. Training-data filters operate on new sealed outputs; verify row-aligned full-FEN state, holdout scope and per-rule accounting. Follow the existing validator training-data reference rather than duplicate that toolchain.

Performance protocol: first same-binary A/A to characterize this host, then paired alternating ABBA or the project's preregistered ordering, pinned resources, warmups and sufficient repetitions. Preserve all runs, medians and dispersion; do not cherry-pick. Fixed-node timing measures cost for fixed work; fixed-depth differing nodes mixes search changes with speed. Identical deterministic nodes/scores and options-OFF pins must be checked on the candidate itself. Shared-VM noise, Linux measurements or Wine runs do not certify a small native Ryzen/Windows gain.

Retain demonstrated small speed improvements. Keep promising noisy results inconclusive; do not turn them into Elo. Search/evaluation changes go through the project's equal-time paired Fastchess acceptance protocol separately.
