# Independent review and validation scope

The seven explicitly requested skills extend the existing package rather than create overlapping routers. Author/reviewer agents used isolated file ownership and original failing-before regression fixtures. No controlled study of general model improvement is claimed; these are helper correctness, integration, structural and bounded application reviews.

Concrete findings repaired during review:

- Native trace/timing records needed their own binary/net/options/suite bindings; replacing a top-level candidate reference must not reuse old results.
- Hashing a file before/after a scan could miss replacement/restoration during the scan; verify consumed bytes and descriptor/path identity, preserving Windows ctime semantics.
- Gate artifacts/options must match the proof's tested binaries/net/options, not merely source commit names.
- A normal-completion race could masquerade as a killed/resumed fixture. Require a nonzero child exit, no next committed checkpoint and a genuinely partial next output.
- Finding LTO/PGO flags anywhere in logs is insufficient: final use/link commands need effective flags, actual profile witnesses and missing/outdated-profile errors must fail.
- A sanitizer PASS receipt cannot override a diagnostic in the preserved native log.
- Relative argv paths and protected-root ancestor directories needed refusal in the PowerShell preflight.

The Linux helper tests include actual subprocess fixtures and a real interruption of only a newly created disposable worker. Original failed logs and partial outputs remain preserved. The native proof fixture is rejected by gate packaging rather than mislabeled ready for production.

PowerShell 7.4.6 from the official PowerShell Linux release was used outside the repository for AST parsing and selected pure-helper/C# pipe-drain tests. This does not establish Windows PowerShell 5.1, D-drive, Windows affinity or a complete native launcher run. No grok-pc operation occurred. The complete private 013/014, authoritative NPT decoder, real pipeline restart, native Forge LTO+PGO/perft/sanitizer run and actual fens12k/ABBA run remain UNVERIFIED.

Every PASS in fixture logs is scoped to that fixture/helper. Installed/discovered/behavior-tested skill states remain separate; crew installation is still a client action. Existing positive engine gains and earlier code/evidence were not changed.
