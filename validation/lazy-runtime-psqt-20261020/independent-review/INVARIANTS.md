# Lazy runtime PSQT review invariants

Read-only design review against committed `15a59cdc` (production fc51); no actively changing implementation was inspected and no engine/compiler ran. This is a checklist for the forthcoming stable implementation, not correctness or speed acceptance.

1. **Exact cached quantity.** At every valid stack entry, PSQT equals the existing White-relative packed `Score` sum: white uses `Psqt+(type-1)*64+square`, black subtracts the vertically flipped-square term. Phase equals the **unclamped** sum of `PhaseValue[type]` for both colors. Clamp only at the existing taper point. A position above24 followed by a capture must not lose the excess phase; promotion changes the piece-type phase, not merely its square. Keep existing packed-score carry/extraction, scale, tempo, taper division, side-to-move sign and residual clamp semantics. Do not independently truncate/repack mg/eg lanes or introduce signed overflow in a new intermediate. Baseline: `src/eval.cpp:383–467`, `include/forge/eval.hpp:10–24`.

2. **Lifetime and current parameters.** Each Worker's new search must rebuild its runtime PSQT values/root sum from the current `params::table`, and invalidate all descendant states before they can be consumed. A Board constructed before a parameter change must work; the same Worker and Board reused in a later search must not inherit the previous search's PSQT. No cache enters Board/make-unmake state or a global shared mutable table. Concurrent mutation during search is not part of the existing parameter contract. Existing TT/pawn-cache reuse behavior must not be silently changed to obtain parity. Baseline: live-table contract in `include/forge/eval_params.hpp:78–82`, root initialization `src/search.cpp:1321–1335`.

3. **Lazy chain, not evaluation frequency.** Cache validity must mean both a matching position and the current search's parameter snapshot. In-check nodes, TT score cutoffs, cached TT static eval and excluded searches can skip evaluation. Replay every dirty edge from a valid ancestor, including unevaluated intermediate nodes, without reading a stale ancestor or crossing the initialized root. Any direct-refresh fallback must refresh PSQT/phase from the same current Board as NNUE. A shared NNUE-valid flag is sufficient only if every path establishing that flag also establishes the PSQT state. Baseline: `static_evaluate` at588–603; TT/excluded paths at897–912.

4. **Every child transition and reuse.** `record_move` must invalidate the reused child's new state before each legal normal/qsearch/ProbCut move; promotion, capture, en passant and both castles replay the existing `DirtyPieces` exactly. Null move uses zero changes: piece sum and raw phase stay identical while final side-to-move/tempo evaluation changes normally. An unmake returns to the unchanged parent; siblings overwrite/replay their own edge. Singular excluded re-entry at the same stack address and PVS/reduced-depth re-search of the same child must not double-apply an edge. Baseline: `src/nnue.cpp:218–240`; `src/search.cpp:820,952–955,990,1068–1071,1095`.

5. **Keep the optimization's boundary narrow.** Only residual-NNUE Worker HCE may consume precomputed PSQT/phase. NNUE-disabled/unavailable HCE and non-residual network behavior remain unchanged. Public `Evaluator::evaluate`, `evaluate_uncached`, `Searcher::evaluate`, full coefficient tracing and tuning tools must retain current-parameter semantics; a trace cannot skip PSQT coefficient accumulation. No float-lane order, network weight, inference path or correction-history behavior changes. Baseline: `src/search.cpp:588–603`, `src/eval.cpp:478–490`.

Bounded validation witnesses for the stable candidate: direct cache-versus-full-scan packed-score/raw-phase equality across all move classes and null; a skipped-intermediate ancestor chain; sibling and excluded/re-search reuse; phase>24 followed by capture and promotion; parameter edit after Board construction and between Worker searches; public traced/evaluation parity; then exact fixed-depth full-engine nodes/moves/scores/PVs against the frozen parent. Include sanitizer coverage for stack indexing and packed arithmetic. Existing special-move fixtures can supply witnesses; no duplicate corpus is needed. Measure performance only after equivalence passes, using the existing calibrated finite protocol. A faster PSQT helper alone does not establish whole-engine speed or Elo.
