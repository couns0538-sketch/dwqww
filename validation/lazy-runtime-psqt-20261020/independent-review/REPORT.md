The root setup invalidates both caches and refreshes PSQT from the current Board and current table on each search that enters iterative deepening. Existing terminal/zero-budget/expired-budget early returns do not consume static evaluation and therefore need no cache. Board creation time and a previous search's PSQT do not determine the new cache. Mutation during an active search is outside the existing live-parameter contract; no new synchronization or TT/pawn-cache policy is introduced.

The original NNUE nearest-ancestor walk, update calls/order and network evaluation remain intact. The added integer update follows each unchanged NNUE update. Separate PSQT validity handles an NNUE-valid/PSQT-invalid entry: invalidity propagates through replay, then the current Board is fully refreshed before residual HCE consumption. This also covers in-check or TT-skipped intermediate evaluations. `record_move` invalidates the child's PSQT whenever it records the existing dirty edge; `record_null_move` preserves the previous zero-dirty NNUE behavior and invalidates PSQT too. Siblings overwrite the edge; re-search at the same position consumes an already matching state rather than applying it twice. Excluded re-entry itself changes no Board or parent cache. No NNUE weights, float-lane operation, Board transition, search pruning or correction-history update was edited.

PSQT refresh and deltas retain the existing packed `Score` representation and white/black square/sign conventions. New arithmetic promotes terms before negation/addition, accumulates in `int64_t`, and casts to `Score` only after a representable-range check. Thus no new overflowing signed delta intermediate or out-of-range narrowing is introduced. Out-of-range states remain invalid and use the existing full evaluator path; this does not claim to repair pre-existing arbitrary-extreme-parameter overflow behavior. Raw phase accumulates piece-type contributions without clipping until the unchanged final taper. Promotions, en passant, captures and castling reuse the existing dirty-piece encoding; null has no piece/phase delta.

Only private Worker-facing evaluator entry points consume the cache, and only in the residual-NNUE path. Public cached/uncached evaluation and traced evaluation retain the original live-table PSQT loop. Trace coefficient accumulation, scale, tempo, taper, sign and residual clamp remain unchanged. NNUE-disabled/unavailable evaluation still calls the original evaluator; non-residual inference returns the network value without the runtime HCE. The11 boundary files in `UNCHANGED-BOUNDARIES.json` were independently rehashed, including Board, NNUE implementation/weights, evaluation parameters and tuners.

The permanent test calls the actual private Worker path through the existing friend and compares its result with the full public evaluator plus the same NNUE accumulator. It separately checks exact packed PSQT and **raw** phase, child invalidation, repeated same-position evaluation, unmake, three siblings, skipped ancestor replay, null and a real child after null, both castling directions/colors, all four promotions/colors, capture promotion, en passant, phase25→24 capture, current parameters after FEN construction, Worker reuse after restoring parameters and public trace coefficients. Those are useful contract checks rather than an alternate implementation accepted on its own.

The retained parent RED is344 checks with227 missing-cache failures; its ordinary Worker/public evaluation equality checks pass. That demonstrates absence of the proposed cache contract, **not an old evaluation bug**. The current fixture differs from the preserved RED fixture only by a poison helper and correction of the invalid-ancestor setup: it now invalidates the nearest valid NNUE ancestor's PSQT and poisons the child's valid PSQT, so failure to propagate invalidity cannot pass accidentally. The earlier setup invalidated the root while a nearer NNUE ancestor was already valid. Both fixture identities are preserved; do not call them byte-identical tests.

Remaining validation is material: full11-test Release success, frozen19 ASan/UBSan and TSan coverage, exact cold/warm full-engine nodes/moves/scores/PVs against the parent, then the authorized performance protocol. The direct test reuses the same NNUE accumulator as its oracle and does not itself prove independent float parity or force every live TT/excluded-search branch. The unchanged float source and lazy structure support the design, but actual full-search parity supplies that evidence. No whole-engine speed or Elo conclusion follows from reducing the PSQT scan.
