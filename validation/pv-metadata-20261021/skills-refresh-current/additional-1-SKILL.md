# Chess Engine Tool Router

Select relevant tools automatically, without requiring the user to name them. Use the smallest sufficient set; do not run every connected plugin for the same question.

## Establish scope

Read the current request and available skill catalog. Preserve the accepted baseline, role boundaries, exact-behavior contracts, CPU restrictions, and existing schedules. Treat remembered versions and earlier assistant reports as retrieval leads, not verified current evidence. Read project data through its connected source before drawing conclusions.

## Route the work

Load only the matching available companions:

| Work | Companion |
| --- | --- |
| Authorized strength development | `improve-grokchess` |
| JavaScript/TypeScript speed with identical behavior | `optimize-grokchess-speed` |
| Correctness, UCI, perft, SMP, or match acceptance | `validate-chess-engine` |
| Hourly research and tester/developer coordination | `chess-research-handoff` |
| Repeated workflow gap or skill improvement | `skill-creator` |

Read [tool-map.md](references/tool-map.md) to select connectors. Discover each tool's actual schema before invocation. A plugin name, installation, or discovery result is not evidence that its action ran. Use native execution for measurements; research and code-review output are hypotheses, not benchmark results.

## Keep automatic use bounded

Use relevant connected reads and already-authorized isolated actions. Do not change permissions, install services, incur new charges, change schedules, merge code, or modify the accepted baseline merely because tool use is automatic. Respect safety and authorization denials; do not try a different interface to evade them. Report connection failures and continue independent work with an authorized alternative.

When a recurring gap is concrete, inspect existing skills, then use `skill-creator` to create or improve a focused skill. Preserve a complete validated package. Distinguish created, packaged, installed, available, invoked, and behavior-tested states. Never claim global installation, future execution, or successful publication without confirmation.

End with the result, evidence, and material limitations rather than a tool inventory. Use [routing-scenarios.md](references/routing-scenarios.md) when evaluating changes to this router.
