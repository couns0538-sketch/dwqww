## Integrity and resource assessment

The format reader validates fixed header/version/size relationships before mapping, and validates record nibbles, score/HCE sentinel ranges and metadata while reading. The writer reserves a prefix with exclusive creation, retains partial columns, and publishes paired files through no-replace hard links. Its behavior on filesystems lacking hard-link support is failure, not replacement. The top-level tools require new output directories and keep failure evidence. A POS path by itself is not a complete seal.

The filter's kept-only duplicate state, original-index near window, fixed rule order and batch speculation accounting agree with the documented policy. FEN alone cannot recover earlier repetitions or game identity.

Native requests are framed and bounded; the owned clients validate response identity/operation, retain IPC, verify clean exit and executable identity, and account for responses. Filter/relabel consumers check requested full state and budgets. Workers are limited to three in the data entry points, each native probe uses one search thread, and the slice relabeler has finite count/batch limits. The SQLite cache and per-worker Hash settings are explicit; no universal hard memory cap is claimed.

The active full run uses its archived earlier publication code, so acceptance still requires its eventual completed manifest and independent checker. The checker validates covered file bytes, sealed/final receipts, ordered counts, paired headers and optional all-record FEN alignment. It explicitly does not independently recompute holdout membership or replay native semantics.
